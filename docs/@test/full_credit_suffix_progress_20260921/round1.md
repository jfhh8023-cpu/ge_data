# REQ-071 第1轮：五类工时后缀识别 + 可编辑进度 — 需求基线

2026-09-21；设计审查，运行 NOT RUN。

## 原始需求

填写页当前仅当需求标题**精确等于** 请假、培训、公司会议、出差、团建 时视为五类有效工时。改为：标题等于上述词组，**或标题末尾（忽略尾部特殊字符与数字）以上述词组结尾**（如 `XXXX请假`、`XXXX“请假`、`xxxxx”请假“`、`XXXXX‘请假’@@`、`XXXXX请假【【23`），且简体/繁体均识别——从后往前数最近的汉字文本是上述词组即命中；命中后同样给默认版本号、工时自己填写。这些记录的交付进度**默认 100%，可编辑**；进度不到 100% 时与其他未完成需求走同一套逻辑（加权统计、未完成列表、跨周带出）。

## 基线需求（R1）

1. 识别：`isFullCreditRecord(title)`＝去掉首尾空白 → 去掉**尾部所有非汉字字符** → 繁体归一（請→请、訓→训、會→会、議→议、團→团）→ `endsWith` 五词组之一。
2. 版本：命中后版本仍为自动 `vYYMMDD` 并锁定（REQ-064 不变）；PM/需求方仍为"不适用"。
3. 进度：命中行进度默认 100，可选 1/10..100；提交/暂存/CRUD/导入若省略或为空 → 100；显式值须在合法集合内。
4. 统计：五类工时按"同人+版本+标题"分组取最新周期进度加权（与普通需求相同）；null（历史）按 100；有效已交付仍全额计入。
5. 未完成列表（REQ-069）与跨周带出（REQ-070）纳入进度 <100 的五类记录。

## 反哺（用例暴露的缺口）

- "特殊字符和数字"未定义英文字母是否忽略（`请假abc`）→ R2 定义：**尾部所有非汉字**忽略（D1）。
- 五类带出行版本：`normalizeFullCreditRecord` 忽略客户端版本并按今日日期重生成 → 带出行版本变化 → 与上周不同组 → 上周 40% 永远"未完成"、每周重复带出 → R2 必须解决。
- 历史五类记录进度全部为 null：展示"不适用"还是"100%（默认）"→ R2（D2）。
- 标题从五类改为普通、或普通改五类时进度如何切换 → R2。
- 需求进度平均（requirementProgress）/需求总数是否纳入五类 → R2。
