日期：2026-09-17。性质：实施前需求/测试设计审查，以下均为待执行用例，非运行通过报告。

## 输入与计划

输入为用户已确认演示及本轮开发授权。按“填报 → 保存/API → 已有表 → 周期统计/卡片详情 → 导出”梳理，采用原存储字段与页面，不进行数据回填或额外改版。

## 基线用例

| 编号 | 输入/动作 | 预期 |
| --- | --- | --- |
| R1-F-001 | 分别输入五类精确标题，人工输入 3.5h | 显示日期固定版本、进度不适用；hours 始终3.5，不自动8/40。 |
| R1-F-002 | 普通标题“培训系统开发” | 普通规则，不能因包含培训而算特殊。 |
| R1-M-001 | 容量40h；普通16h@50%、8h@100%、8h@50%；特殊8h | 总/有效40h、有效100%、加权70%、需求进度62.5%、覆盖100%。 |
| R1-M-002 | 上例增加普通无版本8h | 总48h，有效40h和两交付率不变；无版本只记录。 |
| R1-P-001 | 当前离职人员历史有记录 | 所有范围不显示、不计分子/容量/人数，原记录保留。 |
| R1-A-001 | 未授权令牌请求填报/管理写入口 | 保持原拒绝行为，不因特殊类别绕过权限。 |

## 用例反哺需求与缺口

- R1-F-001 不能只验证“自动版本显示”：标题来回切换可能覆盖工时或普通版本，需增加状态转换及跨日编辑用例。
- R1-M-001 未覆盖 null 与0：加权数学须明确最新进度未知时的结果，不能套用旧空值转零逻辑。
- R1-P-001 只覆盖离职排除，未覆盖恢复/仅部分周有记录造成容量变化。
- R1-A-001 需要服务端验证伪造版本、产品/研发角色来源和失败时数据保留。
