# 部门图表独立验收记录

日期：2026-09-16。

## 方法

- 延续 `verify_stats_record_order_ui.js` 的只读 API 与浏览器内存 fixture 流程；独立脚本为 `backend/scripts/verify_stats_chart_layout_ui.js`。
- 研发柱宽测量来自 Canvas 实际 fill 路径边界；产品柱宽来自渲染后 DOM 边界。未复制应用的布局公式作为预期。
- 多人 fixture：研发 3 个归属组、产品甲/乙 2 名人员、4 种需求方。产品原始总工时为 40h/20h；需求方权重分别为 60/40 与 40/60。
- 检查右图人员分组、四类需求方与总计、零值开关、姓名点击跳转筛选以及再次点击恢复；保存桌面和 390px 截图。

## 发现与修复跟踪

1. 初次零值开关自动化定位落在 Element Plus 隐藏 input，造成 click 超时。这是脚本问题；改为点击可见 switch core，关闭后每人 5 柱，开启后每人 3 柱，复测通过。
2. 真实只读数据发现研发柱顶数值相交：`400.0/400.0`、`196.0/203.0`、`182.0/182.0`。18px 柱宽与 8px 间隙下，数值字宽约 29px，大于 26px 柱中心距。主代理修复整数尾零显示并根据最长数值为左右图统一增加必要间隙，柱宽维持18px。
3. 最终批次 `2026-09-16T13-14-17-538Z` 复测桌面 fixture 与真实数据：两侧柱宽仍均18px，真实数据左右数值标签相交均为0，真实截图已人工复核。右卡实测440px，五项图例顶部位置均650.3125px，全部位于卡片边界内。原始失败及修复后结果均保留于 results.jsonl。

## 已有证据

- 多人桌面左右实际柱宽均为 18px，产品展示页复用组件的柱宽一致。
- 移动页面 `document.scrollWidth = innerWidth = 390`。左图滚动区 286/536px、右图 278/324px，均可局部横向滚动保留柱宽。
- 右图标签产品甲/产品乙；图例含四种需求方与总计；总计40/20h，不重复分摊。
- 部门点击产品甲后进入 AI 产品展示且仅显示其记录，再点该姓名恢复全部人员。
- 未写业务数据库、未发送通知。桌面和移动 fixture 验证无 console/page/HTTP 错误。

图表元素截图在滚动时可能包含固定页头；完整移动页面截图 `department-charts-mobile-full.png` 用于整体布局复核，局部滚动量单独记录在 results.jsonl。
