# 范围一致、全量排序及图表缩放：定向验收矩阵

日期：2026-09-16。初始计划于实现前准备；现已执行，8组最近结果全部PASS。实际范围和边界见 `scope-sort-zoom-review.md`，状态见 `scope-sort-zoom-status.md`。

## 本轮边界

- 周期统计卡片、主列表和分析弹窗使用一致的当前筛选范围，原始工时不因多产品经理归属重复统计。
- 可排序业务列在完整数据集上排序后分页，包括文本、工时/百分比/计数、周次和创建日期。
- 部门左右双图分别放大和还原；移除“AI产品展示”“AI研发展示”顶层页签，保留部门双图及研发/产品聚焦入口。
- 保留有版本计交付、无版本仅记录、未填人员列出及容量去重规则。
- 只允许真实 GET；隔离浏览器 fixture 不写数据库，所有非 GET/HEAD/OPTIONS 的 API 请求拦截，不发送通知。新增结果和截图独立归档，不覆盖此前验收结论。

## 代码与证据依据

- `frontend/src/views/StatsPage.vue`：当前卡片、`analysisRecords`、`analysisScopeCapacity`、`flatTableData`、`pagedAnalysisRows`、周期/来源/人员筛选与分析导出。
- `frontend/src/components/StatsRecordTable.vue`、`StatsProgressTable.vue`：原始记录、需求聚合与展开子表。
- `frontend/src/components/ProductHoursChart.vue`：两侧共用的图表组件，人员名称点击、隐藏零值及响应式分组。
- `frontend/src/stores/stats.js`、`backend/src/routes/stats.js`：`GET /stats`、`GET /stats/progress-details`、个人与 PM 详情、筛选参数。
- `analysis-restored-review.md`、`person-delivery-review.md`：13 分析页签、独立分页、全部历史、有/无版本、岗位子弹窗、人员容量与 390px 基线。

准备时已知旧实现风险（不是新实现缺陷结论）：`pagedAnalysisRows` 先切片再交给表格内建排序，可能只能页内排序；`flatTableData` 从 PM 分组展开，同条多 PM 记录可能重复；旧产品主列表过滤与卡片/弹窗使用的数据源不同。验证必须独立从原始记录 ID 计算预期，不能从这些分组或现有卡片反推。

## 最小测试数据设计

采用独立浏览器 route fixture，复用既有 Playwright 依赖和安全拦截方式：

- 47 条原始记录，至少 3 名研发、2 名产品、1 名无记录人员，4 类需求来源，2 个当前周与 1 个跨年历史周。
- 不把创建时间、工时、需求名、人员名设置成相同顺序；最新记录不是最大工时，最大值位于默认第 3 页，最小值位于第 2 页；同键与缺失值保留可识别 ID。
- 重复 PM 归属仍共用同一个原始记录 ID；产品多来源使用已保存权重。重复容量条目按人员+日期去重。
- 预期计算只读 fixture 原始数组，先按 task/role/staff/source 条件筛选、去重原始 ID，再求和；容量独立从有效人员/任务单位中的日期去重计算。排序预期采用独立 comparator，不导入应用排序 helper。
- 真实本地数据仅用于一轮当前/单周 API 交叉核验和最终视觉截图；不把旧 Q3 数字写死为新版所有范围的预期。
