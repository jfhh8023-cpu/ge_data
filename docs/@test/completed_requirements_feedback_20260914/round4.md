# 第4轮：全链路回归、视觉契约与问题收口

## 继承

继承第1至第3轮已验证的数据口径、需求方均摊、稳定人员 ID 分组、历史进度、分页与页面结构要求。第4轮只收口已发现问题，不扩大产品范围。

## 新增探索用例

| ID | 场景 | 预期 |
| --- | --- | --- |
| API-REG-01 | 真实 `/api/stats` 返回的进度字段回归 | 只出现空值或 0~100 的数字，不把布尔值、空白、越界值带入统计 |
| UI-REG-01 | AI产品展示在 1280/1920 宽度加载 | 产品经理按人员 ID 分组、需求方柱状图可见、无横向滚动条、无控制台错误 |
| UI-REG-02 | 点击产品经理名称后筛选及刷新 | 同名不同 ID 可分别筛选，名称展示不泄漏内部 ID |
| BUILD-01 | 前端生产构建 | `npm run build` 成功 |
| RUNTIME-01 | webhook、重试、节假日、值班换班、历史分页回归脚本 | 既有稳定链路全部通过，失败必须记录为问题而不能静默跳过 |

## 本轮修复

- 进度归一化统一为 `null` 或 0~100 数字，非法值计入未填写，不参与加权分母。
- 产品经理图表改用 `staff_id`/`staff.id` 稳定分组，保留姓名作为展示文本。
- 页面测试从 `networkidle` 改为 DOM 就绪加业务节点就绪，避免 Vite 长连接导致误报。
- 旧子通知调度脚本必须与正在运行的应用调度器隔离；共享本地数据库时，应用进程可能先消费夹具并按生产安全策略拒绝本地 webhook，这属于测试环境竞争，不得放宽生产校验。

## 判定规则

所有新增用例均写入 `runs/<run-id>/results.jsonl`。PASS、FAIL、BLOCKER、ISSUE、TOOL_ERROR 分开记录；未能执行的用例必须写明原因与复现证据。
