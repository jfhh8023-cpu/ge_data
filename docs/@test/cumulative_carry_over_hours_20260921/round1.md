# REQ-072 第1轮：跨周需求累计工时口径 — 需求基线

2026-09-21；设计审查，运行 NOT RUN。

## 原始需求（摘要）

需求进度 <100% 时，下次填写自动带出并回显上次实际状态与进度，并提示"这是上一周的进度，已回显可继续填写"。填好后新进度记入当前周；上周记录保持不变；同一需求跨周不重复记工时，只是进度跨度长。示例：上周 70%/10h → 本周 80%/15h → 下周 100%/18h，需求总体 18h；或上周 70%/10h → 本周 100%/10h，总体 10h。计算总数时把此前工时减去并明显提示；本周任意修改工时不改变逻辑。本周填 15 而此前 10 → 提示"含W36周填写的10小时 + W37（本周）填写的5小时"，上周数字橘色；本周总数统计不含上周工时（小字说明）。填写小于历史工时不允许：失焦自动恢复上次数值。

## 基线需求（R1）

1. **累计口径**：对同人+`version.trim()`+`requirement_title.trim()` 分组，历史工时 `H`＝所有更早任务该组记录 `hours` 之和；填写页工时输入框显示/编辑的是**累计值 C**；当前周期入库 `hours = C − H`（≥0）。
2. **来源**：`H` 与逐周明细由服务端只读计算，随 GET 返回，用于带出行与本人当前任务已提交/草稿行。
3. **提示**：工时单元格下方显示 `含第36周 10h（橘色）+ 第37周（本周）5h`；多周时逐周列出橘色。
4. **总数**：页面"工时总计"仅含当前周期增量；旁小字 `不含此前周期已填 10h`。
5. **下限**：C < H 不允许，失焦自动恢复为上一次有效值并提示。
6. **历史不变**：不改任何既有记录、不改表结构、统计代码口径不变（累加各周期即累计）。

## 反哺（用例暴露的缺口）

- 再次打开（005）需要服务端在**有记录/草稿时也返回历史工时**，REQ-070 只在空时返回 → R2 定义 `carry_over_history` 常返。
- 0h 记录（003）：`buildDeliverySummary` / 前端 `summarizeDelivery` 对 `hours=0` 是否纳入分组以更新最新进度 → R2 核对代码。
- 草稿：整行快照 `hours` 若存累计值，恢复时再加 H 会重复 → R2 定义持久化统一为增量。
- 标题/版本被改动（REQ-070 D2 脱钩）后 H 应视为 0，否则误减 → R2。
- 服务端如何防止客户端把累计值直接当增量提交/负数 → R2。
- 同周同组两行、Excel/识别导入同标题行是否挂接历史 → R2。
