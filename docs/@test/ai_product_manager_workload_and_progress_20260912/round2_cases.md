# REQ-048 第2轮测试用例

目标：反查字段、交互、页签和布局是否足够明确。  
来源：第2轮需求反哺文档。

| 编号 | 类型 | 场景 | 步骤 | 预期 |
| --- | --- | --- | --- | --- |
| R2-UI-001 | UI | 新增产研人员文案 | 打开团队人员页和新增弹窗 | 两处均显示新增产研人员，旧文案不出现 |
| R2-UI-002 | UI | 角色选项 | 角色配置、人员新增、人员编辑分别打开下拉 | AI产品经理、AI开发工程师、VOIP工程师、AI质量工程师、嵌入式工程师完整一致 |
| R2-UI-003 | UI | 研发新行 | 打开研发填报并新增一行 | 进度列在操作列之前，默认为空且显示十档下拉 |
| R2-UI-004 | UI | 产品填报 | 打开AI产品经理填报 | 列名为需求方，四个选项可多选，同时显示交付进度且为必填 |
| R2-UI-005 | UI | 粘贴成功预览 | 粘贴四列 TSV 和空版本 TSV | 每行正确拆出版本、标题、需求方、工时，保存前可修正 |
| R2-UI-006 | UI | 粘贴失败 | 粘贴非法需求方、缺工时、非数字工时、额外列 | 错误行明确标红并阻止整体保存，不静默丢弃 |
| R2-UI-007 | UI | 全角色提交校验 | 研发和AI产品经理分别只填标题、工时，不选进度；直接调用 API | UI 和 API 均拒绝；历史旧行不受影响 |
| R2-UI-008 | UI | 页签默认 | 打开有产品/非产品冲突的统计列表 | 非AI产品经理页签默认选中，第二页签为AI产品经理 |
| R2-UI-009 | UI | 页签筛选保持 | 选择季度/岗位后切换页签 | 时间、人员、岗位筛选保持，数据仅按来源切换 |
| R2-UI-010 | UI | 卡片布局 | 桌面、平板、80%-125%缩放观察卡片 | 总工时后第二张为AI产品经理，无横向滚动条，标题可读 |
| R2-S-001 | 统计 | 进度弹窗 | 点击岗位卡片 | 总览、需求进度两个页签，显示综合进度和任务数分布 |
| R2-S-002 | 统计 | 版本分离 | 创建同标题有/无版本号两条任务 | 弹窗分别列出，不合并 |
| R2-S-003 | 统计 | 100%样式 | 将任务进度设为100% | 所有相关位置显示已完成100%，任务行绿色 |

## 反哺发现

1. 需要明确“操作列之前”的确切列顺序及产品页是否显示进度。
2. 需要明确粘贴工时的小时上限、小数精度和空版本规则。
3. 需要把页签冲突矩阵扩展到报表、导出和需求明细，不只验证周期统计。
4. 需要定义统计 API 的来源字段，避免前端靠页面猜测。

以上进入 R3。
