# REQ-070 第1轮：未完成需求跨周回显 — 需求基线

2026-09-20；设计审查，运行 NOT RUN。

## 原始需求

填写工时时，若某需求交付进度 <100%，下一周填写工时时自动把该需求带出回显（上一周的版本号、需求名称、其他全部参数、进度百分比），以便本周完成到 100%；达成 100% 后该需求按 100% 计算；历史周期已提交的 <100% 记录及其百分比保持不变。

## 基线需求（R1）

1. 打开填写页且当前任务存在时，若本人在**更早周期**有普通有版本需求，其**最新周期**填报进度已知且 <100，则在表格中预置一行：`requirement_title`、`version`、`product_managers`（研发）/`demand_sources`+`demand_source_weights`（AI产品）、`delivery_progress`=上次进度；`hours` 留空由本人填写。
2. 预置行可编辑、可删除；提交后成为当前任务的普通记录，写入路径与手填行完全一致。
3. 历史记录不改写；统计沿用 REQ-066 "同人+版本+标题分组取所选范围最新周期进度" —— 本周填 100 后该组按 100 计，历史行原值保留。

## 现状核对（代码事实）

- 分组与"最新周期"已存在：`backend/src/services/DeliverySummaryService.js` `groupKey`/`isLater`；前端 `utils/deliverySummary.js` `groupRequirementProgress`。**需求第 3 点已由现状满足，无需改动统计。**
- 填写页数据入口：`GET /api/fill/:token`（`routes/fill.js`）返回 `records`/`draft_records`；前端 `FillPage.vue` onMounted 按 草稿 → 已提交 → 空行 三选一初始化 `rows`。
- 历史任务查询已有：`GET /api/fill/:token/history` 通过 `WorkRecord`/`ProductManagerWorkRecord` 的 `staff_id` 汇总任务。
