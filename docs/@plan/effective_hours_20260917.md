## 1. 目标与顺序

1. 文档门控：完成需求基准、四轮反馈与本计划；不新增未决产品口径。
2. 共用规则与后端：将五类识别、版本日期锁定、空进度处理放入明确边界的公共规则；检查填报/编辑入口、产品及研发两来源与统计范围。复用已有字段，无新表或迁移。
3. 前端填写页：手填工时不变，标题识别联动只读版本及不适用进度；保留普通输入草稿；压缩顶部预估两列与说明。
4. 统计：统一人员资格及容量来源，新增加权与需求进度/覆盖率；指标卡与详情逐项 Tips；保留现有图表、列表、页签、排序、默认范围和导出。
5. 审查、执行测试和归档：自动计算/API检查 + 浏览器正常/边界验证与截图，确认历史数据与权限不受影响。报告实际执行结果、未覆盖项，不把设计检查写成运行通过。

冻结用例及预期见 [round4.md](../@test/effective_hours_20260917/round4.md)，每项记录 PASS / FAIL / NOT RUN 与证据路径。至少覆盖普通有版本、普通无版本、五类各一项、空/零进度、当前离职与恢复、跨周期、同名不同 ID、产品/研发隔离、空范围、零容量、接口拒绝、导出一致和桌面/窄屏布局。

数学测试使用内存构造记录；写入接口测试优先用隔离测试夹具或事务回滚，不在当前业务记录上试改。浏览器从实际本地页面验证；不得触发通知。构建检查与语法检查要记录准确命令和结果，不因既有构建警告夸大为本次错误。
