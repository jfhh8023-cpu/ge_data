## 1. 计划原则

- 按“主数据 → 填报 → 存储 → 统计 → 报表/导出 → 全系统回归”顺序开发。
- 每个模块完成 API/数据验证和浏览器验证后，才进入下一个模块。
- 不直接改历史工时；数据库迁移采用扩展-验证-收缩，所有写入放入事务。
- 产品工时和研发工时分别存储，统计层以带来源类型的统一 DTO 汇总。
- 任何一项 P0 用例失败，回退到对应模块，不得继续扩大改动。

## 3. 四轮计划

### 第1轮：需求基线和数据流

输入：原始需求 + `ai_product_manager_workload_and_progress_20260912.md`。  
输出：`round1_cases.md`。

开发准备任务：

- 画出研发填报、PM填报、周期统计、报表导出的接口契约。

### 第2轮：字段、交互与页面冲突

### 第4轮：全系统回归与冻结

输入：R3 用例发现。  
输出：`..._r4.md`、R4用例及冻结清单。

开发准备任务：

- 执行浏览器端到端：新增人员 → 生成链接 → 填报 → 统计 → 报表 → 导出。
- 执行离职/留职/长假、空值/零值、重复提交、网络失败和权限越权回归。
- 检查桌面、平板、缩放 80%-125% 和窄屏无横向滚动。
- 形成发布前回滚步骤；用户确认后才建立开发分支。

门禁：R4 无 P0/P1 未解决项，用户确认冻结三件套后才允许编码。

## 5. 回滚策略

- 角色：停用新角色入口，保留历史键和已保存数据。
- 填报：前端关闭新入口；新表只读；研发旧接口继续读取历史字段。
- 统计：切换到旧 DTO/旧页签，确保历史总工时和人员数恢复。
- 数据库：只回滚本次新增表/新增列，不删除既有记录；生产回滚前必须有备份和行数/合计基线。
