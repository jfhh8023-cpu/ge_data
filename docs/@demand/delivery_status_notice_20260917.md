# REQ-069 进度选项与周期交付状态（冻结需求）

2026-09-17。状态：本地实施与定向验收完成，未部署生产。四轮设计反馈先于业务开发完成。进度步长曾询问可选澄清，超过已提供答复时间未收到回复；采用主代理已告知的默认：保留10%档位并新增1%，倒序100、90…10、1。此为明示默认假设，不表述为用户已选择某选项；如后续回复则跟进。

## 1. 填报输入

填写需求进度选项改为100%在最上、最低1%，集合为100、90、80、70、60、50、40、30、20、10、1。新普通正式提交/导入的前后端校验与选项一致；0、负值、超100及集合外值不允许。历史明确0读取保留，重提交仍需正进度；真实原普通null兼容、原有值清空防绕过及五类进度不适用保持。不改历史记录或字段结构。

## 2. 卡片状态与查看

在周期统计卡片原脚注位置显示状态；保留四指标同行、总工时、原列表与弹窗人员内容。按卡片显示的两位小数交付率比较，顺序如下：

1. 率缺失/非有限或日历无效：**“交付率暂无法计算”**。
2. 两率有效且加权率>有效率：**“数据统计需确认”**，先于无工时判断，即使有效工时为0也不忽略异常。
3. 有效率可计算但有效已交付工时<=0：**“当前周期暂无有效交付工时”**。
4. 正有效工时且两率相等：**“周期内需求交付进度100%”**；Tips说明旧null按100%兼容仅用于计算，不代表原值回填。
5. 正有效工时且加权率<有效率：**“部分需求需跨周期完成。查看”**，提供查看入口。

点击查看打开当前卡片对应范围的未完成需求列表，列为“第X周、人员、需求、当前进度”。数据与卡片的角色/人员/周期范围一致，复用同人+版本+标题、范围内最新周期进度分组。只列真实已知 `0<=进度<100` 的普通有版本需求；历史null按加权兼容处理但不列为低进度，五类不列，普通无版本不列，同组早期低而最新100不列。周取该组当前范围最新记录所属周，优先显示“第X周”，降序；缺周号保留可用周期信息，不伪造周号。列表只读，不更新记录。

## 3. 不变与边界

沿用REQ-066的周期容量加权公式、人群/离职/日期规则和REQ-067人员真实进度显示；替代REQ-068只隐藏脚注的展示结果，新增状态说明而非恢复需求进度/覆盖两项常驻值。历史100默认、明确0、五类全额、缺填周容量及普通无版规则不变。只做输入允许值/排序及状态与只读弹窗必要改动，无迁移、生产或真实测试写库；保护无关脏文件。
