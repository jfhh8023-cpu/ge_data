# REQ-065 加权交付率口径与四指标同行（冻结需求）

日期：2026-09-17。状态：用户已确认公式并要求纠正，四轮设计反馈完成；本地实现与定向验收完成，未部署生产。冻结内容如下；实际结果见[执行验收](../@test/weighted_delivery_refinement_20260917/execution.md)及[开发记录](../@development/weighted_delivery_refinement_20260917.md)。

## 1. 已确认变更

- 周期统计卡片与卡片弹窗左上摘要的“应交付工时、有效已交付、有效交付率、加权交付率”按此顺序同一行展示。保留总工时和其他原信息，不恢复外卡逐人记录；窄屏也要可读，不裁字、不让页面横向溢出。
- **统计加权交付率 = Σ（有效工时 × 需求进度）÷有效工时 ×100%。** 五类工时按100%参与；普通无版本不进入分子和分母。有效工时为0时显示“—”。该指标不再使用工作日容量作分母，不因工作日容量为0或日历待核实而隐藏已有有效工时的进度。
- 人员单独显示其本人的加权率；岗位/部门/所选组直接合并该范围有效工时后计算，禁止对每个人的百分比简单平均。例如A 8h×100%、B 32h×50%，组率为60%，不是75%；全部有效工时进度100%时，组和每人均100%，不受应填工时影响。
- 沿用同人、同版本、同标题、所选范围最新周期进度及来源去重规则。**历史缺失进度按100%参与计算，不更新数据库原始null；历史明确0仍按0。** Tooltip明确历史默认值的兼容规则，不能把计算默认显示成用户已经填报100%。原始进度覆盖率仍表示真实填报覆盖，不能因兼容默认值被伪造为100%。
- 新填写普通需求必须选择正进度，使用既有10%步长，即10、20…100；null、0、负数和非既有步长均不能正式提交。仅数据库原始记录为普通需求且进度原为null时允许兼容保留；已填进度改空、五类改普通均需正进度。历史0只在读取/统计及未重提该字段时保留，重新显式提交普通行0需改为正数。必须校验真实记录归属与原始值，不能仅凭客户端旧记录ID或豁免标记绕过新行约束。五类进度不适用，规则不变。

## 2. 两个名称不同的指标

| 指标 | 页面 | 分母及含义 |
| --- | --- | --- |
| 加权交付率 | 统计卡片/详情/逐人/导出 | 有效工时；衡量已记录有效工作的需求进度。 |
| 预估加权工时完成度 | 填写页 | 所属周期应填工时；衡量当前表单加权工时相对工作日容量的完成度。仍为预估，不能随统计公式改动而换成有效工时分母。 |

填写页保持两个紧凑预估指标及现有五类提示。普通新行未选进度继续提示待填写，不用历史兼容规则自动替人填新进度。普通已有空/零值与新行校验分开，不批量更改原值。

## 3. 不变与最小边界

有效已交付、有效交付率、总工时、容量、人群/周期、五类手填工时与固定日期版本、原表格页签排序、普通无版本仅记录、离职过滤等保持 REQ-064。只替换冲突公式/新行进度校验及必要布局、Tips和导出文案；无迁移、回填、生产操作或示例数据插入。

本条覆盖 REQ-064 中统计加权率“除以应交付工时”、历史null导致待补进度，以及新行允许0的冲突部分；其余不变。已批准的本轮纠正是开发授权，归档不新增产品决策，不重复索取相同许可。
