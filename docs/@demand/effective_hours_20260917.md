## 2. 五类工时

- 需求标题去除首尾空白后，**完整匹配**“请假、培训、公司会议、出差、团建”，统一作为特殊有效工时。“培训系统开发”“公司会议纪要”等不匹配。
- 工时由人按实际情况填写，保留既有工时校验；识别标题、切换类别、恢复普通需求都不得填入默认工时、覆盖或清空已填工时。
- 新填特殊工时自动生成且锁定版本号 `vYYMMDD`，按首次填写当天中国时区日期；例如 2026-09-17 为 `v260917`。之后编辑保留原日期版本，不按编辑日重新生成。
- 从普通需求切到五类时保留普通版本及进度草稿；五类之间切换不覆盖草稿；切回普通需求恢复草稿。自动日期版本不得意外成为普通需求版本。
- 特殊工时的需求进度为“不适用”，不强制进度、产品经理、需求方；不写伪造 100% 进度。前后端均执行同一分类规则，服务端不能被手工版本或伪造进度绕过。
- 五类工时按原始人工工时只计一次，计入总工时、有效已交付、有效交付率及加权交付率，不参与普通需求填报进度、进度覆盖率和需求数。
- 既有五类标题即使版本为空也按特殊工时统计；只读兼容，不批量改写历史版本、进度、工时或时间戳。日期版本不是需求唯一 ID，不能据此合并不同人员或类别。

## 3. 人员与范围

- 以人员**当前**状态为准，`resigned` 不显示、不统计，包括历史范围；不删除历史记录。改回任何非离职状态后，原始数据正常参与相应范围。
- 非离职人员在所选过滤范围内有实际保存记录才存在；没有记录不补零行、不占人数或容量。保留工时零值和空进度的区别，预览草稿不当作已保存记录。
- 先确定整个所选范围的有记录人员，再按这些人员在所选范围内的完整工作日容量统计，每人每天 8h，同人同日去重；不能因其中一周没填记录再扣除该周容量。
- 继续沿用实际工作日、法定节假日及调休数据。无效或零容量显示“—”，不除零。人员按 ID 区分；产品填报作者和需求归属产品经理不可按同名混淆。
- 卡片、弹窗摘要、逐人统计、下方列表及导出共享范围；每次打开弹窗跟随主页面，仍允许单独切其他范围或全部历史，关闭重开恢复页面范围。

## 4. 指标契约

| 名称 | 计算与空值行为 |
| --- | --- |
| 总工时 | 所选范围全部有效记录原始工时，包括普通无版本及五类特殊工时；不因进度空值剔除。 |
| 应交付工时 | 所选范围有记录且当前非离职人员的工作日容量 × 8h。 |
| 有效已交付 | 普通有版本工时 + 五类工时；先分五类，避免自动版本造成重复计算。普通无版本仅展示记录。 |
| 有效交付率 | 有效已交付 ÷ 应交付工时 × 100%。不封顶，100% 及以上保留绿色完成背景。 |
| 加权交付率 | （普通有版本需求累计工时 × 该需求范围内最新周期填报进度，再求和 + 五类原始工时）÷ 应交付工时 × 100%。普通需求有未知进度时显示“待补进度”，不能当 0/100 或省略后虚增结果。 |
| 需求填报进度 | 普通有版本需求中已知进度的累计工时加权平均；五类、普通无版本不参与。 |
| 进度覆盖率 | 有已知进度的普通有版本工时 ÷ 全部普通有版本工时；无普通有版本工时显示“—”。 |

普通需求去重键为人员 ID + 版本 + 精确需求标题，保持研发/产品来源身份；仅在所选范围内累计工时，以范围内最新周期进度为准，同周期以保存时间及稳定 ID 判断最新。最新记录进度空值必须保持未知，不回落到较旧已知值。显式 0% 是有效进度。现无永久需求 ID，不引入跨标题模糊合并或数据库迁移。

示例：每周容量 40h，普通需求分别 16h×50%、8h×100%、8h×50%，培训人工填 8h，则总工时/有效已交付均为40h，有效交付率100%，加权交付率70%。普通需求填报进度为20÷32=62.5%，覆盖率100%。普通无版本再加8h时总工时48h、有效已交付仍40h。

## 5. 页面与说明

- 填写页紧凑两列显示“预估工时完成度”“预估加权工时完成度”，两者明确为预估，仅计算当前表单，不叠加保存前记录造成双算。前者为全部表单人工工时÷本周容量；后者按上述有效及进度规则计算。说明与五类工时提示一起显示，桌面高度目标约为原来一半，窄屏自然换行。
- 周期统计外卡及详情使用“有效已交付”“有效交付率”，新增“加权交付率”，以紧凑辅助区显示需求填报进度及覆盖率；保留右上角总工时大字。
- 鼠标放到每一个数据均有独立 Tips：公式、当前数值代入、范围和空值口径；有效已交付必须解释“普通含版本号的数据，以及请假、培训、公司会议、出差、团建数据”，避免仅改名称。
- 外卡不显示逐人记录；弹窗上方保留重点摘要和逐人表，下方保留总览首位的原分析页签、排序分页、原始列表和导出。部门淡青背景、四项计数等既有布局保留。
- 保留底部研发及其他人员/AI产品经理两个填报页签、原分组表、姓名跳转、双图总计折线、无横向拖动条及独立缩放。本需求不另行改版这些模块。

## 6. 最小范围与覆盖关系

沿用现有 Vue/Node 架构和存储表，仅修改必要的统一规则、录入校验、统计过滤/计算及页面展示。无数据库迁移、历史回填、生产数据操作、示例数据插入或通知发送。导入遵守既有权限和历史保护；导出采用同范围同指标，保留既有公式注入防护。失败保存不得改变原数据。
