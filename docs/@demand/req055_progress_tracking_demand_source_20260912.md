# REQ-055 统计进度追踪、需求方目录与全链路详情需求文档

状态：`REVIEW_REQUIRED`，四轮反哺完成，待用户确认冻结。

## 1. 业务目标

让研发工时和 AI产品经理工时在统一周期统计框架中可追踪、可解释、可下钻、可导出，同时维护可扩展的需求方目录，避免固定枚举、维度混淆和历史统计失真。

## 2. 功能要求

### 2.1 详情与进度

所有可点击工时卡片进入统一详情弹窗，默认“总览”，并提供“全部追踪和进度”“普通版本（有版本号）”“无版本号版本”。当前范围按已有年份/季度/任务筛选；全部范围仅取消时间限制，保留权限、人员、岗位、来源等其他条件。每页显示范围元数据。

所有综合进度可点击查看参与记录、有效工时、空进度记录、状态分类和加权公式，并支持只读 Excel。有效记录必须满足工时大于 0 且进度为数值；历史空进度不进入分母。公式 Tips 必须包含 `Σ(有效工时×进度)÷Σ有效工时` 和 `10h×100%+2h×50%=91.67%`。

### 2.2 产品展示与部门双图

AI产品展示按产品人员和需求方双维度展示卡片、柱图、列表、排序、奖牌、弹窗、跳转和导出。产品需求方图支持点击名称/柱子，携带当前查询条件进入产品详情。部门展示保留研发归属人图和产品需求方图，研发图宽、产品图窄，单柱宽一致，窄屏纵向堆叠且无横向滚动。

### 2.3 需求方目录

管理员可以新增、编辑、停用需求方，字段为稳定 ID、名称、颜色、排序、启用状态和 revision。名称唯一且经过长度/颜色校验；新填报只显示启用项。已引用项不能删除，确认弹窗列出引用数量和类型，确认后仍返回 409；允许改名且保持 ID 和历史关联。统计、填报、导入、报表、导出全部从目录读取。

### 2.4 来源与历史

研发和产品工时继续独立存储，统一返回必须带 `source_type`。多需求方记录保存一次原始工时，图表按权重拆分，卡片和原始列表不重复。旧静态报告保存目录 revision 和名称快照，新报告用当前目录。历史展示层的 `-`/百分比规则不能改写统计原始值。

## 3. 数据与权限

需求/版本复合键至少包含来源、人员、任务、规范化版本和需求标题；需求方另带稳定 ID。所有写接口服务端校验管理员权限、参数、名称唯一、引用和 revision。导出服务端重算并防止公式注入。
