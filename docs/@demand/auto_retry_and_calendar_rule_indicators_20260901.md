# 自动任务失败重试与日期规则角标需求文档

## 文档信息

- 日期：2026-09-01。
- 状态：`LOCAL_IMPLEMENTED_AND_VERIFIED`。
- 触发需求：自动消息或规则执行失败后每 5 分钟重试，单笔计划最多尝试 3 次；任务一旦生成不得重复创建；全年日历和日期详情标题需清晰标识特殊通知、人员跳过、临时换班，并默认展示当天完整规则。
- 实施边界：仅修改当前开发环境；本轮不推送远端仓库、不发布生产。
- 关联需求：`REQ-042`、`REQ-043`。

## 1. 产品目标

1. 临时网络、钉钉接口或数据库故障不再导致自动任务永久漏执行。
2. 重试只延续同一笔原计划，不创建新的业务任务、不改变原计划时间。
3. 任务创建成功但通知失败时，后续只重试通知，禁止再次生成收集任务。
4. 管理员在全年日历中无需逐日打开即可识别哪些日期配置了特殊通知、人员跳过或临时换班。
5. 选中日期后默认看到当天全部规则信息，再按页签进入编辑。

## 2. 失败重试范围

### 2.1 纳入自动重试

- 自动任务创建并通知：任务创建失败、通知发送失败。
- 自动值班通知：开始提醒、结束提醒发送失败。
- 子通知：满足前置条件并到达计划时间后的发送失败。
- 特殊日期通知：到达特殊通知时间后的发送失败。

### 2.2 不纳入自动重试

- 页面上的“测试执行”“测试发送 webhook”“子通知测试发送”等人工测试操作。
- 管理员主动停用、删除的规则或通知。
- 已成功执行的计划。
- 业务校验明确判定为“已存在/无需创建”的自动收集任务。

## 3. 重试状态机

1. 首次真实计划执行记为第 1 次尝试。
2. 失败后写入失败原因和下一次重试时间：当前尝试时间加 5 分钟。
3. 第 2 次仍失败，再等待 5 分钟执行第 3 次。
4. 第 3 次失败后停止自动重试，保留最终失败状态和完整错误信息。
5. 任意一次成功后立即结束该计划的重试链，清空下一次重试时间。
6. 服务在重试发送过程中异常退出时，恢复后仍按同一笔计划和剩余次数继续，不重新建立计划。
7. 重试到点期间规则被停用时不得发送；重新启用后可继续尚未耗尽的原重试链。

## 4. 任务生成幂等

### 4.1 唯一身份

- 自动执行日志继续使用 `规则 ID + 原计划时间 + 事件类型` 作为唯一键。
- 所有重试沿用原日志，不新增另一条代表同一计划的运行日志。

### 4.2 创建保护

- 收集任务创建与 `created_task_id` 回写必须处于同一数据库事务。
- `created_task_id` 一旦存在，所有后续尝试直接进入通知补发分支，不再调用任务创建函数。
- 创建前继续按自然周和起止日期查询现有收集任务；命中已存在任务时视为业务跳过，不创建重复任务。
- 即使通知失败、进程重启或调度器重复扫描，也不得生成第二笔相同周期任务。

## 5. 运行记录与可观察性

每笔自动计划至少保存：

- `attempt_count`：已执行次数，范围 0-3。
- `last_attempt_at`：最近尝试时间。
- `next_retry_at`：下一次重试时间；成功、跳过或次数耗尽时为空。
- `retry_payload`：值班通知重试所需的原始事件快照，不保存 webhook 密钥。
- 原计划时间、事件类型、创建出的任务 ID、通知状态和最后错误。

设置页历史记录应显示“第 N/3 次失败、将在 5 分钟后重试”或“已达到 3 次上限”的清晰文案。

## 6. 日历日期角标

### 6.1 日期格角标

日期存在对应草稿或已保存数据时，在日期格右上角显示：

| 数据类型 | 角标 | 颜色 |
| --- | --- | --- |
| 特殊通知 | `特` | 蓝色底、白色字 |
| 人员跳过 | `跳` | 橙色底、白色字 |
| 临时换班 | `换` | 红色底、白色字 |

- 同一天可同时显示多个角标。
- 临时换班的两个日期都显示“换”。
- 删除对应草稿后角标实时消失；保存后重新加载仍应准确回显。
- 特殊通知只要存在已配置内容、@ 配置或已开启发送，即视为有数据；默认空表单不显示角标。

### 6.2 底部页签标题角标

- 当天有特殊通知数据时，“特殊通知”标题显示 `特`。
- 当天有人员跳过数据时，“人员跳过”标题显示 `跳`。
- 当天有临时换班数据时，“临时换班”标题显示 `换`。
- 标题角标和日期格角标必须使用同一组计算函数，避免状态不一致。

## 7. 日期规则默认完整详情

1. 每次选中或右键定位日期，默认打开“日期规则”页签。
2. “日期规则”除日期类型、停排结果、是否配置、覆盖状态外，还要展示：
   - 当天基础值班人员和最终值班人员。
   - 特殊通知是否启用、触发时间、@ 范围和完整文案。
   - 人员跳过名单。
   - 当天涉及的全部临时换班记录及双方日期、人员。
3. 无数据时明确显示“未配置”或“无”，不留空白造成误判。
4. 各编辑页签保留现有编辑能力，不改变保存接口和草稿机制。

## 8. 验收标准

### 8.1 自动任务与通知

- 第 1 次失败后 `next_retry_at` 为约 5 分钟后，尝试次数为 1。
- 第 2 次失败后再次延后 5 分钟，尝试次数为 2。
- 第 3 次失败后不再生成下一次时间，尝试次数为 3。
- 第 2 或第 3 次成功后状态为成功，后续不再触发。
- 任务已创建、通知失败的场景中，数据库收集任务始终只有一笔，重试仅调用通知。
- 同一规则、计划时间和事件类型只存在一条运行日志。
- 子通知和特殊日期通知遵守相同的 5 分钟/3 次上限。
- 人工测试失败不会进入自动重试队列。

### 8.2 日历

- 分别配置“特”“跳”“换”后，对应日期格和底部标题均实时出现角标。
- 一天配置三类规则时三个角标同时显示且不遮挡日期、农历和值班人员。
- 换班双方日期都显示红色“换”。
- 删除规则后角标立即消失，保存并重新打开后状态一致。
- 选中任意日期默认打开完整详情，所有字段与实际草稿/保存数据一致。

## 9. 风险与控制

- 多 webhook 中部分成功、部分失败时，本期沿用现有整笔通知失败语义，重试整笔通知；运行日志明确记录失败目标，后续可按 webhook 粒度扩展去重。
- 重试不保存 webhook URL 或 token 快照，发送时读取规则当前有效 webhook 配置，避免敏感配置进入运行日志。
- 数据库新增字段全部采用兼容性缺列补列，不覆盖现有业务数据。
- 本轮仅本地开发和验证，不执行生产数据库操作。

## 10. 本地实施结果

- 自动任务、任务通知、值班开始/结束提醒、子通知和特殊日期通知均已接入 5 分钟重试与 3 次尝试上限。
- 收集任务创建和运行日志任务 ID 回写已纳入同一事务；通知重试复用已有任务 ID。
- 设置页运行历史与子通知列表已显示重试次数、下一次重试倒计时及最终失败状态。
- 日历格、底部页签标题和日期规则汇总已共用同一套“特/跳/换”状态计算。
- 临时换班两端日期均显示“换”，日期规则默认展示基础值班人、最终值班人和全部例外详情。
- 本地自动化、系统联动、前端构建、浏览器交互和临时数据清理均已通过；详细证据见 `docs/@development/auto_retry_and_calendar_rule_indicators_20260901.md`。
