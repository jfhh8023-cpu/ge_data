# 自动任务规则历史默认收起与分页需求文档

## 文档信息

- 日期：2026-09-01。
- 状态：`RELEASED_AND_VERIFIED`。
- 触发需求：规则底部成功失败信息支持分页及每页 `10/20/50/100/200/300/500/1000` 条；2026-09-01 后续明确要求首次进入页面时默认收起。
- 实施边界：初始要求仅当前开发环境；2026-09-01 经用户明确授权后推送远端并发布生产。
- 关联需求：`REQ-044`。

## 1. 数据范围

- 延续现有“规则历史”定义，统一展示 `auto_task_messages` 规则提示记录和 `auto_task_run_logs` 真实运行日志。
- 两类记录合并后按实际记录时间倒序，最新记录始终在前。
- 每条自动任务规则拥有独立的分页状态、每页条数和总记录数，不受其他规则记录数量影响。

## 2. 默认行为

1. 设置页加载成功后，有历史数据的规则默认收起历史区域。
2. 收起状态显示最近一条记录摘要，不渲染历史列表和分页器。
3. 用户点击展开后默认打开第 1 页，每页显示 20 条，即最近 20 条记录。
4. 展开区域不重复渲染同一条最新记录；再次收起后继续显示最近一条摘要。
5. 没有历史记录的规则不显示空分页区域。

## 3. 分页交互

- 可选每页条数固定为：`10`、`20`、`50`、`100`、`200`、`300`、`500`、`1000`。
- 修改每页条数后回到第 1 页并立即加载。
- 支持上一页、下一页、页码和跳转页。
- 显示该规则历史总条数。
- 删除单条、批量删除或全部删除后刷新当前分页；当前页超出剩余页数时自动回退到最后有效页。
- 批量选择能力保持现有语义，可在不同分页间累计已选记录。

## 4. 接口约束

- 新增按规则查询历史的只读分页接口。
- 后端校验规则存在、页码为正整数，并仅接受规定的每页条数；非法每页条数回退为 20。
- 单页最大 1000 条，禁止调用方绕过上限。
- 返回字段包含：记录列表、当前页、每页条数、总条数和总页数。
- 查询使用参数绑定，不拼接规则 ID、页码或每页条数。

## 5. 验收标准

- 页面首次进入后，各条有历史的规则默认收起并显示最近一条摘要。
- 点击展开后显示最新 20 条及分页器。
- 第 21 条及更早记录可通过第 2 页继续查看，顺序不重复、不遗漏。
- 八种每页条数均可选择并真实影响接口返回数量。
- 两条规则分页互不影响。
- 收起时只展示最新一条摘要，再展开时保留当前分页状态。
- 删除后总数、页码和当前列表同步准确。
- 原有状态颜色、重试倒计时、单条删除、批量删除和全部删除保持正常。
- 前端构建、分页 API 自动化验证和本地浏览器交互全部通过。

## 6. 数据保护

- 本需求不修改已有历史记录内容，不迁移或清理业务数据。
- 本地自动化测试仅创建带固定前缀的临时规则及历史，测试结束后全部清理。
- 生产发布使用 `--skip-db`，不上传或导入本地业务数据。
