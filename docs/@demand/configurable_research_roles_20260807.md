# 可配置研发角色与嵌入式软件工程师需求优化文档

## 1. 文档信息

- 日期：2026-08-07
- 适用系统：DevTracker
- 实施环境：仅本地开发环境
- 发布约束：不推送远端仓库、不发包、不发布生产
- 需求来源：本次对话新增需求及既有 AI 岗位、VOIP 岗位、人员状态规则

## 2. 背景与目标

当前研发角色由前后端常量、数据库枚举和报表固定列共同定义。每增加一个角色，都要在人员、匹配组、统计、图表、导入导出和离线报告中分别增加硬编码，容易出现“人员页已修改、分析报告仍使用旧角色”的不一致。

本次目标分为两层：

1. 新增内置研发角色 `嵌入式软件工程师`，完整参与人员管理、工时录入、需求统计、周期统计、AI产品经理统计、导入导出和离线工时分析报告。
2. 将研发角色升级为全局可配置字典。管理员在团队人员页修改角色名称或新增角色后，所有业务页面和数据报表均使用同一份角色定义，不再依赖页面硬编码。

## 3. 用户故事

### 3.1 人员管理员

- 我可以按姓名、手机号码、角色、状态筛选研发人员，快速定位目标人员。
- 我看到的新增按钮名称是“新增研发人员”，不会和 AI产品经理混淆。
- 我可以打开“角色配置”，查看现有角色，编辑角色完整名称、简称和颜色。
- 我可以新增一个研发角色，并马上用该角色新增或编辑研发人员。
- 我修改角色显示名后，历史人员和历史工时仍关联同一个角色，系统所有位置统一显示新名称。

### 3.2 研发人员

- 我的角色可以是嵌入式软件工程师或管理员新增的其他研发角色。
- 我的专属链接、填报权限、在职/离职规则与其他研发角色一致。
- 我提交的工时会归入我当前的角色，并进入需求统计和周期统计。

### 3.3 数据查看者

- 部门全观能看到每个有效研发角色的总工时、图例、图表和明细。
- AI产品经理工时分布图只显示至少有一项指标大于 0 的产品经理，全指标为 0 的产品经理不占横轴空间。
- 需求工时统计、导出文件和离线分析报告能区分嵌入式软件工程师及后续新增角色。

## 4. 统一角色模型

### 4.1 角色定义字段

| 字段 | 说明 | 规则 |
| --- | --- | --- |
| `key` | 稳定角色标识 | 创建后不可修改；系统角色使用固定值，自定义角色由后端生成 |
| `name` | 完整名称 | 2-30 个字符；全局唯一；可编辑 |
| `short_name` | 紧凑名称 | 1-12 个字符；空间不足的卡片、图例、表头使用；可编辑 |
| `color` | 角色颜色 | `#RRGGBB`；标签、卡片、图表统一使用；可编辑 |
| `sort_order` | 展示顺序 | 系统维护；新增角色排在现有角色之后 |
| `is_system` | 是否内置角色 | 内置角色不可删除；本期不提供任何角色删除功能 |
| `is_active` | 是否启用 | 本期默认均启用，不提供停用入口 |

### 4.2 初始角色

| key | 完整名称 | 简称 | 初始颜色 |
| --- | --- | --- | --- |
| `ai_dev` | AI开发工程师 | AI开发 | `#165DFF` |
| `voip` | VOIP工程师 | VOIP | `#00B42A` |
| `ai_quality` | AI质量工程师 | AI质量 | `#FF7D00` |
| `embedded` | 嵌入式软件工程师 | 嵌入式 | `#14B8A6` |

历史值 `frontend`、`backend` 继续兼容并归一到 `ai_dev`；历史值 `test` 继续兼容并归一到 `ai_quality`。

### 4.3 改名与历史数据原则

- 业务数据只保存稳定 `key`，页面展示时实时查询角色定义。
- 编辑 `name`、`short_name` 或 `color` 不重写人员和工时数据。
- 历史记录、当前记录、图表和导出都使用角色当前显示名。
- 角色名称重复、简称为空、颜色格式错误时后端拒绝保存。

## 5. 团队人员页需求

### 5.1 筛选区

研发人员页签在预设文本区和人员表格之间增加单行筛选栏：

| 控件 | 类型 | 匹配方式 |
| --- | --- | --- |
| 姓名 | 文本输入 | 去首尾空格、不区分大小写、包含匹配 |
| 手机号码 | 文本输入 | 去首尾空格、包含匹配 |
| 角色 | 可清空下拉 | 动态加载全部启用角色，精确匹配角色 key |
| 状态 | 可清空下拉 | 在职、离职、留职、长假，精确匹配 |
| 重置 | 按钮 | 一次清空四项筛选 |

筛选只改变当前列表展示，不改变排序和后端数据。无匹配项时显示“未找到符合条件的研发人员”。

### 5.2 顶部按钮

- `新增人员` 更名为 `新增研发人员`。
- 右侧增加 `配置` 按钮，仅研发人员页签显示。
- 刷新按钮继续保留，刷新人员时同时刷新角色定义。

### 5.3 新增/编辑研发人员

- 角色选项从全局角色接口读取，不再使用静态常量。
- 新增弹窗标题为“新增研发人员”，编辑标题为“编辑研发人员”。
- 新增角色保存成功后，无需刷新页面即可出现在人员角色选项中。
- 后端必须校验角色存在且启用，不能仅依赖前端校验。

### 5.4 角色配置弹窗

弹窗标题：`研发角色配置`。

现有角色列表每行展示：

- 颜色选择器/色值
- 完整名称输入框
- 简称输入框
- `保存` 命令按钮

弹窗下方提供“新增角色”表单：完整名称、简称、颜色和“新增”按钮。

交互规则：

- 每行独立保存，保存期间禁用该行按钮。
- 保存成功后刷新全局角色缓存和当前人员列表。
- 角色稳定标识不展示为可编辑字段。
- 本期不提供删除、停用、合并、拖动排序。

## 6. 数据与后端改动

### 6.1 数据库

新增 `staff_roles` 表保存角色字典。

`staff.role` 从 ENUM 改为 `VARCHAR(50)`，保留原数据并允许后续自定义角色 key。

`match_groups` 新增 `role_buckets` JSON 字段，结构如下：

```json
{
  "ai_dev": [{ "staffName": "示例", "hours": 8 }],
  "embedded": [{ "staffName": "示例", "hours": 4 }]
}
```

旧字段 `frontend`、`backend`、`voip`、`test_role` 暂时保留，用于兼容旧代码、历史脚本和回滚；新代码以 `role_buckets` 为主，并在保存内置角色时同步旧字段。

### 6.2 启动迁移

启动时执行幂等迁移：

1. 创建 `staff_roles` 并补齐四个初始角色。
2. 将 `staff.role` 改为字符串列。
3. 将人员历史角色值归一为 `ai_dev` 或 `ai_quality`。
4. 为 `match_groups` 增加 `role_buckets`。
5. 对缺少 `role_buckets` 的历史匹配组，从旧字段生成角色分桶。
6. 迁移过程不删除旧字段、不修改 `work_records` 工时、不改变工时合计。

### 6.3 角色接口

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| GET | `/api/roles` | 返回全部启用角色，按 `sort_order` 排序 |
| POST | `/api/roles` | 新增角色并生成稳定 key |
| PUT | `/api/roles/:key` | 编辑完整名称、简称、颜色 |

所有接口统一返回 `key/name/short_name/color/sort_order/is_system/is_active`。

| 模块 | 现状风险 | 本次要求 |

| 初始化与导入脚本 | 固定 enum/样例角色 | 新 schema、四个初始角色、通用角色分桶 |

## 8. 部门全观零值产品经理图表规则

“按AI产品经理工时分布”图表的数据源在绘图前过滤：

```text
保留条件：角色指标之和 > 0 或 total > 0
隐藏条件：所有角色指标均为 0 且 total = 0
```

- 隐藏对象不进入横轴标签、柱体、柱顶 0 标签和点击命中区域。
- 只过滤该图表；部门明细表、产品经理列表、聚焦页和人员状态逻辑保持原口径。
- 导出的“AI产品经理柱状图数据”与画面一致，也不输出全 0 项。
- 若全部产品经理均为 0，图表显示空状态，不绘制无意义坐标项。

## 9. 角色显示与布局规则

- 空间足够：显示完整名称，如“嵌入式软件工程师”。
- 紧凑图表、卡片小标题、窄表头：显示简称，如“嵌入式”。
- 角色标签统一 `white-space: nowrap`，不得拆行撑高表格。
- 动态列使用最小宽度和横向滚动，不压缩到文字重叠。
- 图表颜色取角色配置；总计继续使用红色，不与角色颜色混用。

## 10. 数据口径

- 在职、留职、长假研发人员按既有规则统计；所选时间无工时则值为 0。
- 离职人员沿用既有时间范围规则：离职前已有数据可查，离职后无数据的阶段不显示姓名且不统计。
- 角色配置改名不改变任何工时数值。
- 人员改角色后，统计按查询时关联的当前人员角色口径展示；本次不新增角色变更历史表。
- 匹配组总工时必须等于各角色分桶工时之和。

## 11. 验收标准

### 11.1 角色配置

1. `/api/roles` 初始返回四个角色，包含嵌入式软件工程师。
2. 可新增自定义角色并用于新增研发人员。
3. 可修改完整名称、简称、颜色；刷新后仍保留。
4. 重名、空名称、非法颜色、未知角色 key 均被后端拒绝。

### 11.2 人员页

1. 按姓名、手机号、角色、状态分别筛选及组合筛选准确。
2. 按钮显示“新增研发人员”和“配置”。
3. 角色标签完整、单行、颜色正确。
4. 嵌入式人员及自定义角色人员可新增、编辑、填报和状态切换。

### 11.3 工时与报表

1. 嵌入式及自定义角色工时进入独立角色分桶，不误入 AI开发、VOIP 或 AI质量。
2. 需求工时统计动态列支持显示、编辑、自动保存、刷新回显。
3. 部门统计、研发聚焦、产品经理聚焦、明细和导出均统计动态角色。
4. 离线工时分析报告所有页签使用动态角色名称、简称和颜色。
5. Excel 模板、导入、导出和全量备份均覆盖动态角色。
6. 改角色名称后，历史工时合计不变，所有页面显示新名称。

### 11.4 零值 PM 图表

1. 全角色和总计均为 0 的 AI产品经理不显示在柱状图。
2. 任一角色大于 0 的 AI产品经理正常显示。
3. 明细表和产品经理聚焦不因图表过滤丢失业务数据。

### 11.5 质量门槛

1. 前端生产构建通过。
2. 后端主要文件语法检查通过，服务可正常启动。
3. 数据迁移前后人员数、工时记录数、工时总和守恒。
4. API 自动化回归覆盖角色 CRUD、人员校验、统计动态键、报表动态分桶。
5. 浏览器验证人员筛选、角色配置、动态报表列和零值 PM 图表，无控制台错误、无遮挡和文字换行。
6. Git 仅保留本地改动；无提交、无推送、无生产发布。
