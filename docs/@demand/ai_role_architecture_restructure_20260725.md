# DevTracker 团队岗位重构优化方案与详细需求文档

日期：2026-07-25  
范围：本地环境先行优化，不发布生产，不推送远程。  
背景：实际团队架构已重构，不再按“前端/后端/测试”拆分岗位。系统需统一为“AI开发工程师 / AI质量工程师 / AI产品经理”的新业务口径，同时兼容历史数据可查。

## 一、优化目标

1. 研发岗位统一：
   - 历史“前端”与“后端”统一归并为“AI开发工程师”。
   - 历史“测试”统一改为“AI质量工程师”。
2. 产品经理名称统一：
   - 所有用户可见页面、导入导出模板、接口错误提示，将“产品经理”统一展示为“AI产品经理”。
3. 历史数据兼容：
   - 历史 `frontend/backend/test` 数据不删除。
   - 统计时 `frontend + backend + ai_dev` 统一进入 AI开发工程师。
   - 统计时 `test + ai_quality` 统一进入 AI质量工程师。
4. 数据同步与统计一致：
   - 需求工时统计、周期统计、研发聚焦、AI产品经理聚焦、PM 专属页、静态分析报告采用同一角色口径。
   - 手动新增行、自动保存、导入导出与后端统计字段同步。
5. 离职规则延续：
   - 仅“离职”人员后续不统计、名单不可见。
   - 在职/留职/长假继续按新岗位正常统计。
   - 离职前已有历史数据仍在对应时间范围可查。

## 二、角色与数据模型

| 新业务角色 | 系统主键值 | 兼容旧值 | 说明 |
| --- | --- | --- | --- |
| AI开发工程师 | `ai_dev` | `frontend`, `backend` | 前端、后端历史记录统一并入开发统计 |
| AI质量工程师 | `ai_quality` | `test` | 测试历史记录统一并入质量统计 |
| AI产品经理 | `product_managers` 数据源 | 产品经理旧文案 | 数据结构保持独立 PM 表，展示名称统一 |

数据库策略：
- `staff.role` 支持 `ai_dev/ai_quality`，并保留旧 enum 值用于兼容迁移。
- 本地启动时执行角色迁移：`frontend/backend -> ai_dev`，`test -> ai_quality`。
- `match_groups` 继续保留 `frontend/backend/test_role` 三个历史列，新增接口语义：
  - `ai_developers = frontend + backend`
  - `ai_quality = test_role`
  - 新增/编辑时优先写入 `ai_developers` 到 `frontend` 兼容列，`backend` 置空。

## 四、接口与兼容要求

### 人员接口

`GET /api/staff`
- 返回 `role` 使用新值：`ai_dev` 或 `ai_quality`。
- 可附带 `legacy_role` 供排查迁移来源。
- 可附带 `role_label`，展示为 AI开发工程师 / AI质量工程师。

`POST/PUT /api/staff`
- 仅允许新角色值。
- 旧值若传入，后端可归一化，但前端不再提供旧选项。

### 统计接口

`GET /api/stats`
- `roleSummary.ai_dev`：AI开发工程师总工时。
- `roleSummary.ai_quality`：AI质量工程师总工时。
- 保留兼容别名：`frontend=ai_dev`，`backend=0`，`test=ai_quality`。
- `pmDistribution` 每个 AI产品经理同样提供新字段与兼容别名。

### 报表接口

`GET /api/report`
- 返回 `ai_developers` 和 `ai_quality`。
- 旧 `frontend/backend/test_role` 仍返回，用于兼容历史代码和数据审计。

`PUT /api/report/:id`
- 优先接受 `ai_developers` 和 `ai_quality`。
- 若使用新字段保存，`backend` 兼容列置空。

`POST /api/report/manual-row`
- 支持新字段整行自动保存。

`POST /api/report/import`
- 新模板按新字段导入。
- 旧模板继续兼容，旧前端/后端合并为 AI开发工程师。

## 五、验收标准

1. 人员管理新增/编辑岗位仅显示 AI开发工程师、AI质量工程师。
2. AI产品经理相关页面、弹窗、模板、接口错误提示统一显示“AI产品经理”。
3. 历史前端/后端工时在统计里合并到 AI开发工程师。
4. 历史测试工时在统计里合并到 AI质量工程师。
5. 需求工时统计手动新增行可编辑所有业务字段，并自动保存。
6. 周期统计页面与静态分析报告不再显示旧三端结构。
7. 旧 Excel 模板、旧 match_groups 存储结构仍可读，不影响历史数据查询。
8. 离职/在职/留职/长假规则保持既有业务含义，仅岗位口径变化。

## 六、风险与后续建议

1. `match_groups` 仍使用历史列名，短期有利于兼容，长期建议增加正式字段 `ai_developers`、`ai_quality` 后做数据库迁移。
2. 历史导入脚本和 `demo/` 静态演示仍存在旧字段样例，非主系统运行路径；后续若要公开 demo，需单独重构。
3. 生产发布前必须备份生产数据库，并先执行只读统计对比：
   - 旧前端+后端总和 = 新 AI开发工程师总和。
   - 旧测试总和 = 新 AI质量工程师总和。
4. 上线前需重点验证：人员管理、填写页、需求工时统计、周期统计、PM专属页、静态分析报告、Excel 导入导出。
