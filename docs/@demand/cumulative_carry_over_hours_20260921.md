# REQ-072 跨周需求累计工时口径（冻结需求）

2026-09-21。状态：四轮设计反哺完成，按用户"四轮后按最小改动开发"授权采用默认决策 D1~D6，进入开发。四轮记录：[R1](../@test/cumulative_carry_over_hours_20260921/round1.md) [R2](../@test/cumulative_carry_over_hours_20260921/round2.md) [R3](../@test/cumulative_carry_over_hours_20260921/round3.md) [R4 矩阵](../@test/cumulative_carry_over_hours_20260921/round4.md) · [冻结计划](../@plan/cumulative_carry_over_hours_20260921.md)。

## 1. 用户原始需求

进度 <100% 的需求在下次填写时自动带出并回显上次状态与进度，提示为上一周进度、可继续填写；新进度记当前周，上周记录不变；同一需求跨周不重复记工时。示例：上周 70%/10h → 本周 80%/15h → 下周 100%/18h，需求总体 18h；上周 70%/10h → 本周 100%/10h，总体 10h。计算总数时减去此前工时并明显提示（"含W36周填写的10小时 + W37（本周）填写的5小时"，上周数字橘色）；本周总数不含上周工时（小字说明）；填写小于历史工时不允许，失焦恢复上次数值；本周任意修改工时不改变逻辑。

## 2. 已具备（REQ-070/071）与本条新增

已具备：自动带出、回显标题/版本/PM/进度、"第N周未完成 · 上次进度"标签、上周记录不变、统计按同人+版本+标题累加各周期工时并取最新进度。
新增：**填写页以累计值输入/显示、入库仍为当前周期增量**、历史工时提示、总数小字说明、下限恢复、再次打开保持累计口径、服务端一致性校验。

## 3. 规则

- **分组与历史**：同人 + `version.trim()` + `requirement_title.trim()`；`H`＝所有更早任务（`start_date` 早于当前任务）该组记录 `hours` 之和（含 0h）；仅对"最新更早进度为 0~99 已知值"的组（即 REQ-070/071 带出候选）计算。
- **持久化统一为增量（D1）**：DB、草稿、提交/暂存 payload 的 `hours` 均为当前周期增量；前端行显示值 `C = 增量 + H_eff`。
- **GET 常返历史**：`carry_over_history[{ requirement_title, version, previous_hours, previous_progress, source_task_id/title/week_number/end_date, history_weeks[{task_id, week_number, task_title, hours}] }]`，有无记录/草稿均返回（system 与 legacy）；`carry_over_records` 触发条件不变。
- **挂接范围（D2）**：服务端带出行、当前任务本人已提交行、草稿恢复行按 `(title, version)` 匹配挂接；手工新增/Excel/识别行不挂接。同周同组多行仅首行挂接，其余提示"同名同版本已在上方按累计填写"（D4）。
- **脱钩**：标题或版本被改动（REQ-070 D2）→ `H_eff=0`，显示值即增量，历史提示消失。
- **下限**：显示值 `< H_eff` → 失焦恢复上一次有效值并警告；`= H_eff` 合法（增量 0）。
- **提示**：工时下方 `含 第36周 10h（橘色）+ 第37周（本周）5h`，多周逐周橘色；总计旁小字 `不含此前周期已填 10h（第36周）`。
- **未改动带出行提交（D3）**：写入 `0h/上次进度`，允许。
- **服务端防线（D5）**：`hours<0` 400（既有）；行带 `cumulative_hours` 且匹配本人历史组时校验 `cumulative_hours − previous_hours = hours`（±0.005），不符 400；`cumulative_hours` 不入草稿/DB。
- **统计（D6）**：代码不改；累计即各周期增量之和，最新周期进度决定状态；`0h/100%` 记录使组最新进度为 100 并退出未完成列表。
- 无表结构变更；历史任务编辑模式不带出不挂接；权限/离职/五类版本锁定不变。
