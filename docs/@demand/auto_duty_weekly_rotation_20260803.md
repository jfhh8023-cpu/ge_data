# 自动值班每周轮换模式需求归档（2026-08-03）

实施状态：已完成开发、远端推送和生产发布；生产数据已按备份加 `--skip-db` 方式保护。

## 背景

当前“设置 / 自动执行任务并通知 / 自动值班通知”中，“每周星期值班配置”的值班对象采用固定模式：逐日点击周一至周日，为每一天固定选择值班人员。实际使用中需要保留固定排班，同时支持按周自然刷新、按人员勾选顺序轮换排班。

本需求最初限定仅在本地开发；完成验收修订后，用户于 2026-08-03 明确授权远端推送与生产发布。发布必须保护生产数据，不携带或导入本地数据库。

## 目标

1. 保留现有固定配置方式，并作为“固定模式”单选项继续可用。
2. 在“值班对象”标题右侧新增“轮换模式”单选项，仅作用于“每周星期”值班配置。
3. 轮换候选人沿用当前固定模式候选来源：在职且姓名、手机号可用于钉钉 @ 的研发人员。
4. 后端调度与前端展示使用同一轮换规则，避免页面显示和实际通知对象不一致。
5. 在每周值班概览中明确当前自然周，并提供后续三周排班查看能力。

## 功能需求

### 固定模式

- “固定模式”保持当前行为：点击周一至周日任一天，勾选当天固定值班对象，保存后按该天固定人员通知。
- 月度值班配置不引入轮换模式，仍按现有固定配置执行。
- 旧数据未包含模式字段时，默认按固定模式处理。

### 轮换模式

- 在每周星期值班配置弹窗“值班对象”标题右侧新增单选项：
  - 固定模式
  - 轮换模式
- 当前选中的单选项就是实际保存和执行的 `weekly_mode`，重新打开弹窗时回显已保存模式。
- 选择轮换模式后，可配置排班区间：
  - 周一到周一
  - 周一到周二
  - 周一到周三
  - 周一到周四
  - 周一到周五
  - 周一到周六
  - 周一到周日
- 轮换模式只对区间内日期生效。
- 未被排班区间覆盖的日期，概览显示与当前固定模式“未配置人员”的周六/周日一致，不发送值班通知。
- 被勾选人员按勾选顺序形成轮换序列；排班每天取一个人，跨自然周连续轮换。
- 当人员数多于区间天数时，下一周继续从未排到的人开始；当人员数少于区间天数时，按序循环。
- 勾选人员时，在复选框与姓名中间显示序号：
  - 序号为蓝色圆形背景、白色字体。
  - 取消勾选会移除该人员并重排剩余序号。
  - 若要调整中间顺序，用户通过取消后续人员再重新勾选实现。

### 每周概览

- 仅在轮换模式下，每周值班概览标题右侧显示说明：
  - “当前是第XX周值班人员，下周值班人员每周一早上更新”
  - XX 为当前日期对应的 ISO 自然周。
  - 该说明字号小于“每周值班概览”标题。
- 概览中的周一至周日显示当前自然周的实际排班人员：
  - 固定模式显示固定配置人员。
  - 轮换模式显示按当前自然周计算出的当天人员。
- 点击周一至周日任一天打开的“每周星期值班配置”弹窗，都可编辑固定/轮换模式。
- 固定模式下不显示上述当前周说明及“后续”按钮；轮换模式下恢复显示。

### 后续三周预览

- 每周概览说明右侧新增“后续”按钮。
- 点击“后续”后弹窗展示当前自然周之后连续三周的每日排班。例如当前为第 32 周，则展示第 33、34、35 周。
- 预览应能一眼看出某一周某一天是谁：
  - 按自然周分组。
  - 每组展示周一至周日。
  - 未在轮换区间内或未配置人员的日期显示未配置/跳过。

## 数据设计

沿用 `auto_task_rules.duty_config` JSON，不新增数据库列：

```json
{
  "weekly": {
    "1": {
      "enabled": true,
      "staff_ids": [],
      "start_time": "09:00:00",
      "end_time": "18:30:00",
      "send_mode": "start_only",
      "start_message": "请关注线上告警和待处理反馈。",
      "end_message": "请同步今日值班处理结果。"
    }
  },
  "monthly": {},
  "weekly_mode": "fixed",
  "weekly_rotation": {
    "end_weekday": 5,
    "staff_ids": [],
    "start_date": "2026-08-03"
  }
}
```

字段说明：

- `weekly_mode`: `fixed` 或 `rotation`。缺省按 `fixed`。
- `weekly_rotation.end_weekday`: 排班区间结束星期，1-7，固定从周一开始。
- `weekly_rotation.staff_ids`: 按勾选顺序保存的轮换人员 ID。
- `weekly_rotation.start_date`: 轮换锚点日期，保存为锚点周的周一。用于跨周连续轮换。
- 轮换模式下，`weekly` 仍保存每天通知时间、发送策略、提醒文案；当天值班对象由轮换规则动态计算。

## 后端规则

- `normalizeDutyConfig` 需要兼容旧 JSON，并输出 `weekly_mode`、`weekly_rotation`。
- `getDutyItemForParts` 在 weekly + rotation 模式下：
  - 若当天星期大于 `end_weekday`，返回未启用配置。
  - 若轮换人员为空，返回未启用配置。
  - 否则基于 `start_date` 与当天日期计算 day offset，取 `staff_ids[offset % staff_ids.length]`。
  - 使用当天 `weekly[weekday]` 的通知时间、策略、文案；若当天无配置，则使用默认时间和默认开始/结束文案。
- `isRuleDateMatched`、`getNextRunAt`、定时执行均以动态解析后的值班项为准。
- 保存 duty rule 时，weekly + rotation 模式的 `week_days` 应按排班区间生成，而不是只看固定人员字段。

## 前端规则

- 每周值班详情弹窗在“值班对象”右侧增加模式单选项：
  - 固定模式：显示现有人员勾选网格，保存当前星期固定人员。
  - 轮换模式：显示排班区间、轮换人员勾选顺序、当天生成结果提示。
- 保存详情时：
  - 固定模式按旧逻辑保存当前星期固定人员。
  - 轮换模式保存全局 weekly rotation 配置，同时保存当前星期通知内容。
- 概览与预览统一调用同一前端解析函数展示动态值班项。
- 批量配置弹窗维持现有行为，不扩大本次改动范围。

## 验收标准

1. 旧 weekly duty 配置未含新字段时，页面仍按固定模式展示并可保存。
2. 固定模式下，原勾选人员、保存、预览、测试发送逻辑不回退。
3. 轮换模式下，勾选 B、C、A、D 时显示序号 1-4；取消 C/A/D 后 B 保持 1，再勾选 A 显示 2。
4. 轮换模式选择“周一到周五”时，周六/周日概览显示未配置/跳过，不发送通知。
5. 当前周概览能显示当前自然周每天实际轮换人员。
6. “后续”弹窗从下一自然周开始展示连续三周；当前为第 32 周时展示第 33、34、35 周。
7. 后端 `getNextRunAt` 和 scheduler 对轮换模式按动态值班人员执行。
8. 发布时先推送远端，再备份生产数据库并使用 `--skip-db` 发布；不得将本地数据导入生产。
9. 固定模式保存后概览隐藏当前周说明和“后续”按钮；轮换模式保存后显示，重新打开弹窗时单选状态与后端保存值一致。

## 风险与边界

- 轮换模式仅覆盖每周星期值班；月度值班维持固定模式。
- 批量编辑暂不改造为轮换批量编辑，避免扩大改动范围。
- 若轮换人员后来离职，前端候选列表不再显示该人员；后端 @ 手机号解析也会过滤离职人员。后续如需保留历史排班快照，可另立需求。
- 已失效或不再属于在职候选范围的历史人员 ID 不在概览中暴露，统一按“未配置/跳过”展示；历史 JSON 不自动删除。
