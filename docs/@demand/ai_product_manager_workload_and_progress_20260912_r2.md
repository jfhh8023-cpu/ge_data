# REQ-048 第2轮需求反哺

来源：R1 用例 `R1-M-002`、`R1-D-001~003`、`R1-P-001`、`R1-S-002`。  
状态：已形成交互和字段基线，仍待 R2 测试反哺。

## 1. 本轮修订

### 1.1 身份与存储

- 人员主数据可以在现有人员体系中识别 AI产品经理；产品经理历史身份不强制迁移。
- 工时来源独立：研发记录保留 `work_records`，产品记录使用独立产品工时表。统一统计 DTO 不能反向改变原始存储。
- 所有记录必须带 `source_type` 和人员/角色快照，避免人员后来改角色导致历史统计漂移；具体快照字段名在 R3 设计。

### 1.2 角色显示

- 角色键 `embedded` 不变；已确认显示名统一成“嵌入式工程师”，旧名称作为历史别名可检索。
- 角色下拉、标签、图表、筛选、导出、统计卡片全部读取角色 API。

### 1.3 填报字段

- 研发列顺序最终约束为：需求标题、版本号、AI产品经理、工时/h、交付进度、操作。
- AI产品经理列顺序为：需求标题、版本号、需求方（可多选）、工时/h、交付进度、操作。
- 所有角色的新记录均强制填写进度；产品页面同时保留需求方和交付进度，需求方不是进度的替代字段。
- 粘贴首选 TSV：版本号、需求标题、需求方（可用逗号分隔多值）、工时、交付进度；空版本用空字段。预览后才可保存。

### 1.4 交互与页签

- 统计冲突页面统一使用“非AI产品经理 / AI产品经理”页签，默认非AI产品经理。
- 切换页签不丢失年、季度、周期、人员和岗位筛选。
- 进度弹窗的总览和需求进度是二级页签；版本/无版本号是组内分区，不用第三个大页签。

## 2. 待确认项

- 已确认 AI产品经理也必须填写交付进度。
- 已确认嵌入式旧显示名统一替换为嵌入式工程师。
- 综合进度采用工时加权，详细公式在 R3/R4 冻结文档固定。

## 3. R2 进入条件

R2 用例必须覆盖每个字段的初始值、输入、错误、编辑、导入、草稿、页签默认值和响应式布局；发现的存储或统计问题继续反哺 R3。
