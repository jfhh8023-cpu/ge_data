## 1. 背景与现状

当前自动值班已支持：

1. 每周固定模式。
2. 每周轮换模式及按勾选顺序连续轮换。
3. 年内每月日期固定配置。
4. 固定/轮换规则按指定日期生效、待生效排班和后续三周预览。
5. 开始提醒、开始和结束提醒、钉钉 webhook 与人员 @。
6. 值班候选人使用团队人员数据，当前实现排除离职人员，保留在职、留职和长假人员。

现有排班存在以下缺口：

- 轮换游标按配置星期累计，不知道国家法定节假日、周末手动取消、手动停排日和临时请假。
- 固定/月度配置直接按日期取人员，没有“停排后顺延”的统一解析层。
- 未配置日期虽然不发送通知，但没有与轮换游标、节假日顺延统一建模。
- 没有独立于正常值班通知的节日祝福通知。
- 没有人员单日跳过、临时替补和两日期一对一换班能力。

## 2. 产品目标

1. 在设置页提供全局、直观、可审计的全年停排日配置。
2. 正常值班排期自动跳过周末、法定节假日、手动停排日和规则未配置日期。
3. 被整日跳过的排班人员不丢失，按确认后的顺延规则进入后续有效排班日。
4. 支持某人仅在某日不参与排班，由后续人员顺位补位。
5. 支持两名人员仅在两个指定日期交换值班，后续基础排班保持不变。
6. 支持在不执行正常值班的日期独立发送节日/周末/标记日文案，并可配置是否 @ 人。
7. 页面预览、后续排班、测试发送和后端真实调度必须使用同一解析结果。

## 3. 术语

| 术语 | 定义 |
| --- | --- |
| 默认停排日 | 系统按日期自动识别的周末或国家法定节假日，首次进入当年日历时默认选中 |
| 手动停排日 | 管理员在普通工作日上手动选中的日期，显示绿色 |
| 强制工作日 | 管理员取消默认周末/法定节假日选中状态后形成的覆盖项 |
| 未配置日期 | 当前值班规则在该日期没有可执行的星期/月日模板，天然不产生正常值班事件 |
| 有效排班日 | 日期处于规则范围、存在可用配置、不是有效停排日，且能解析出值班人员 |
| 人员单日跳过 | 某人员在指定日期不参与值班，但日期本身仍是有效排班日 |
| 临时换班 | 两名人员在两个指定日期交换最终值班位置，仅影响这两个日期 |
| 特殊日期通知 | 与正常值班开始/结束通知相互独立的节日或标记日通知 |
| 基础排班 | 不考虑节假日、人员例外和换班前，由固定/轮换/月度规则产生的排班 |
| 最终排班 | 基础排班依次经过整日停排、未配置过滤、人员跳过和换班覆盖后的结果 |

## 4. 功能范围

### 4.1 本期包含

- 设置页标题行入口。
- 当前年份全年日历及年份切换。
- 周末、法定节假日、手动停排和取消默认停排。
- 每条自动值班规则的有效排班预览。
- 周/月底跨界顺延。
- 特殊日期独立通知及 @ 人配置。
- 人员单日跳过。
- 两日期一对一临时换班。
- 调度日志、幂等、防重复发送和冲突校验。

### 4.2 本期不包含

- 自动访问第三方非官方节假日 API。
- 自动读取员工请假系统、钉钉审批或考勤数据。
- 跨团队、跨自动值班规则交换人员。
- 修改已经成功发送的历史通知或补发历史日期。
- 用本地数据覆盖生产数据。

## 5. 设置页入口

### 5.1 位置

- 在设置页标题“设置”所在行的最右侧新增按钮：`节假日跳过设置`。
- 按钮使用日历图标与文字，作为明确命令；不放在“自动执行任务并通知”卡片内部。
- 标题、说明文字和按钮保持同一行；窄屏允许说明文字压缩，但按钮不得换行或被遮挡。
- 仅管理员或具备设置编辑权限的用户可见并可操作。

### 5.2 点击行为

- 点击后打开大弹窗。
- 弹窗建议宽度：`min(1440px, calc(100vw - 48px))`。
- 弹窗建议高度：`calc(100vh - 64px)`，主体纵向滚动，不出现页面级横向滚动条。
- 关闭时若有未保存修改，提示“存在未保存修改”；未修改时直接关闭。

## 6. 全年日历布局

### 6.1 顶部工具区

从左到右显示：

1. 年份选择器，默认当前年。
2. 自动值班规则选择器；只有一条值班规则时可隐藏并直接使用该规则。
3. 图例：周末、法定节假日、手动停排、已取消默认停排、未配置日期。
4. 官方节假日数据来源与更新时间。
5. “恢复当年默认值”命令。
6. “保存生效”主按钮。

### 6.2 日历主体

- 展示选中年份的 12 个月。
- 桌面端建议 3 或 4 列月份网格；小屏降为 2 列或 1 列并纵向滚动。
- 每个日期格尺寸稳定，日期数字、节日简称和状态标识不得撑高整行。
- 当前日增加独立描边；当前正在编辑的日期增加黑色焦点框，不使用另一种填充色，避免与业务状态颜色混淆。

### 6.3 颜色与辅助标识

| 类型 | 主色 | 文本/图标 |
| --- | --- | --- |
| 周末默认停排 | 蓝色 | `周末` |
| 国家法定节假日 | 红色 | 节日简称，如 `国庆` |
| 手动停排日 | 绿色 | `手动` |
| 取消默认停排 | 白色/浅灰底 | `已取消`，保留原类型小圆点 |
| 当前规则未配置 | 灰色斜纹或灰色下划线 | `未配置` |

- 颜色不能作为唯一信息，必须同时提供文字、图标或 Tooltip。
- 同一天同时属于周末和法定节假日时，红色优先，Tooltip 同时列出“法定节假日、周末”。
- 手动停排只用于非默认停排日期；默认停排日取消后再次点击，恢复其默认类型和颜色。

### 6.4 单击选中/取消

- 单击普通未选日期：创建手动停排覆盖，显示绿色。
- 单击蓝色周末或红色法定节假日：取消该日默认停排，变为“强制工作日”。
- 单击绿色手动停排：取消手动标记，恢复普通状态。
- 单击已取消默认停排：恢复默认选中状态。
- 每次单击同时把该日期设为下方详情区的当前日期。
- 所有修改先进入弹窗草稿，只有点击“保存生效”才写入系统。

## 7. 默认日期数据

### 7.1 周末

- 系统按北京时间和公历自动计算当年全部星期六、星期日，首次初始化时默认停排并显示蓝色。
- 周末计算不依赖外部服务。

### 7.2 国家法定节假日

- 以国务院办公厅当年度节假日安排通知为唯一正式来源。
- 开发时将已复核的年度日期快照和来源元数据写入系统，不允许调度器运行时依赖第三方节假日服务。
- 每条官方日期至少保存：日期、节日名称、所属区间、来源标题、来源 URL、数据版本和校验时间。
- 若下一年度官方数据尚未录入，页面只自动生成周末，并在顶部明确显示“该年度法定节假日数据未初始化”，禁止静默使用上一年数据。
- 本文不固化具体 2026 日期；进入开发前必须另行核对并归档当年官方通知原文。

### 7.3 官方调休上班日

- 用户原始要求是“所有周末默认选中”，因此本文暂按字面规则将调休上班的周末也视为蓝色默认停排。
- 是否让国务院通知中的调休上班日自动覆盖周末，是第 15.3 项待确认事项。

## 8. 正常排班日期解析

### 8.1 有效排班日条件

某日期只有同时满足以下条件才可产生正常值班开始/结束事件：

1. 自动值班规则已启用。
2. 日期处于该规则年份、待生效版本和可执行范围内。
3. 对应星期或月日已有可用配置。
4. 日期不是有效停排日。
5. 能解析出至少一名允许参与的人员。
6. 开始文案和发送策略满足现有校验。

任一条件不满足时：

- 不产生正常值班开始/结束事件。
- 不发送正常值班 webhook。
- 不写成功日志；若属于可解释跳过，可写结构化 `skipped` 审计记录。
- 特殊日期通知仍可按第 11 节独立执行。

### 8.2 计算优先级

建议统一按以下顺序计算，前端预览与后端调度不得各自实现不同顺序：

1. 解析日期对应的当前/待生效排班版本。
2. 判断星期/月日是否配置。
3. 应用全局整日停排状态。
4. 计算固定、轮换或月度基础人员序列。
5. 应用人员单日跳过并顺位补人。
6. 应用临时换班覆盖。
7. 校验人员当前状态、姓名和手机号。
8. 构建开始/结束事件。
9. 独立计算特殊日期通知。

### 8.3 整日停排与未配置日期

- 法定节假日、周末和手动停排日均不消耗轮换模式的正常排班名额。
- 未配置日期同样不消耗轮换名额。
- 轮换模式下，轮换游标只按“有效排班日”前进。
- 示例：周四张三、原计划周五李四；周五至周日均停排，则下一有效工作日由李四值班，再下一有效工作日才轮到李四之后的人。
- 月度模式同样跳过不存在的日期（如 2 月 30 日）、未配置日期和停排日。

### 8.4 固定模式与月度固定配置的建议解释

为满足“原定周五李四放到下一工作日”的原始示例，本文建议：

- 把每个已配置日期的人员视为一个按时间排序的“排班单元”。
- 停排日删除日期位置但不删除排班单元；该单元移动到下一个有效配置日，后续单元依次顺延。
- 多人固定值班时，整组人员作为一个排班单元移动。
- 这一规则会使固定模式在节假日之后不再严格保持“星期几永远固定某人”，影响较大，必须经第 15.1 项确认后才能开发。

### 8.5 跨周、跨月和跨年

- 周配置允许从本周顺延到下一自然周。
- 月配置允许从当前月份顺延到下一月份的有效配置日。
- 本文建议不跨 `schedule_year` 自动顺延；年末仍有未安排单元时，在页面显示“待处理冲突”，由管理员选择下一年度规则后处理。
- 待生效排班版本切换日是边界；旧版本未执行单元不得静默穿透到新版本，页面必须提示并由管理员确认保留或丢弃。

## 9. 人员单日跳过

### 9.1 入口与候选人

- 下方详情区提供“人员跳过”页签。
- 候选人员显示姓名、角色和状态，支持多选。
- 候选范围应与现有值班候选逻辑保持一致，还是严格只允许 `active`，见第 15.4 项。
- 离职人员不得新增为跳过对象；历史记录保留 ID 和审计信息，但后续页面按既有离职可见性规则处理。

### 9.2 生效规则

- 人员跳过只作用于选定的自动值班规则和日期，不是全局永久禁用。
- 日期本身必须是有效排班日；若整日停排，人员跳过配置不参与计算，页面显示“整日已停排，无需人员跳过”。
- 若基础值班人员命中跳过名单，按当前人员序列向后寻找第一名未跳过且可用的人员补位。
- 若多人值班，仅移除命中的人员；仍有人员时不额外补位，除非用户确认要求保持固定人数。
- 若全部候选人都被跳过或不可用，该日期显示“无人可补位”，不发送正常值班通知并生成告警。

### 9.3 建议的游标行为

- 本文建议跳过人员的本轮名额视为已消耗，补位人员也消耗本轮名额；下一有效排班日从补位人员之后继续，避免同一人连续重复。
- 示例：顺序 A、B、C、D；周二原定 B，周二跳过 B，则周二 C、周三 D、周四 A；B 等待下一轮。
- 是否按此方式改变后续轮换游标，是第 15.2 项待确认事项。

## 10. 一对一临时换班

### 10.1 配置

- 下方详情区提供“临时换班”页签。
- 选择当前日期和值班人员后，再选择同一规则内另一个日期及该日期值班人员。
- 两个日期必须是未执行的有效排班日。
- 多人值班时，必须明确选择双方各自要交换的人员，只交换被选人员，不交换整组其他成员。

### 10.2 执行

- 换班在整日停排和人员跳过计算完成后应用。
- 两名人员只在两个指定日期交换最终位置。
- 换班不改变轮换锚点、基础顺序和两个日期之后的排班。
- 示例：周二 A、周四 C 互换后，周二 C、周四 A；周三、周五及后续排班不变。
- 换班目标人员若在目标日被标记跳过、已经离职或目标日变为停排日，保存时阻止；保存后人员状态变化导致失效时，调度前自动降级为基础排班并记录告警。

### 10.3 冲突

- 同一日期同一人员只能存在一个有效换班关系。
- 已进入成功发送日志的日期不可新增或编辑换班。
- 取消换班后恢复基础排班加人员跳过后的结果。

## 11. 特殊日期独立通知

### 11.1 适用范围

可为以下范围批量配置通知：

- 单个日期。
- 某个法定节假日区间。
- 当年全部周末或选中的周末。
- 手动标记日期集合。

批量配置建议生成逐日记录，保存后每一天都可以单独修改或关闭。

### 11.2 字段

| 字段 | 规则 |
| --- | --- |
| 是否发送 | 独立开关，默认关闭 |
| 触发时间 | 北京时间，精确到时分秒 |
| 通知文案 | 必填，使用现有钉钉 Markdown 文本安全规则 |
| 是否 @ 人 | 关闭时不 @；开启后弹出人员选择 |
| @ 模式 | 建议支持指定人员与所有人 |
| 指定人员 | 仅展示符合候选规则且有有效手机号的人员 |
| 目标自动值班规则 | 多规则时必选，决定使用哪条规则的 webhook |
| webhook 目标 | 默认使用目标规则全部已启用连接；是否允许细选见第 15.5 项 |

### 11.3 调度与正常值班解耦

- 特殊通知即使当日整日停排也可发送。
- 特殊通知不产生值班人员、不推进轮换游标、不创建值班开始/结束日志。
- 每条逐日通知每个计划时间只允许发送一次。
- 测试发送不得写正式成功日志或占用正式发送幂等键。
- 发送失败记录错误并允许后续人工测试，但不得自动重复轰炸群聊。

## 12. 保存、生效与历史

### 12.1 原子保存

- “保存生效”一次性提交日历覆盖、人员跳过、特殊通知和换班变更。
- 后端必须事务校验；任一冲突失败时全部回滚，不允许部分保存。
- 保存成功显示非二次确认提示，并重新拉取服务端结果。
- 使用修订号进行乐观锁，避免两名管理员互相覆盖。

### 12.2 生效时间

- 已成功发送的历史事件绝不撤销、补发或改写。
- 当前日期尚未到触发时间时，保存后的规则可作用于尚未执行事件。
- 当前日期开始通知已经成功后，不允许再通过人员跳过或换班重写当天开始排班；特殊通知仍可在自身触发时间前配置。
- 首次启用全年节假日后，是否从今天立即重新计算还是从指定日期启用，见第 15.6 项。

### 12.3 审计

至少记录：

- 操作人、时间、年份、规则 ID、修订号。
- 新增/取消的停排日期及原因。
- 人员跳过名单变化。
- 换班双方和日期。
- 特殊通知开关、时间、目标和结果；日志中不得保存 webhook token。

## 13. 页面状态与错误提示

## 15. 已确认业务决策

### 15.1 固定与月度模式的节假日顺延

- 决策：固定周/月配置也把排班单元顺延到下一有效配置日，后续单元依次顺移，严格满足“李四放到下一工作日”。
- 影响：节假日之后，固定星期与原人员关系会发生变化。

### 15.2 人员单日跳过后的后续顺序

- 决策：跳过人员和补位人员的本轮名额都消耗，下一日从补位人员之后继续，避免补位人员连续值班。

### 15.3 调休上班周末

- 决策：按原始要求，所有星期六/星期日默认停排；国务院通知标记为调休上班的周末仍默认停排，但展示“调休上班”标识，管理员可单击取消。

### 15.4 候选人员状态

- 决策：继续沿用现状，在职、留职、长假均可参与，仅排除离职。

### 15.5 多规则和 webhook

- 决策：全局停排日作用于所有自动值班规则；人员跳过、换班和特殊通知绑定具体规则。特殊通知发送到该规则全部启用 webhook，本期不逐条细选 webhook。

### 15.6 首次启用的生效边界

- 决策：首次保存选择“今天起/指定日期起”，默认从下一未执行排班日开始；过去日期只展示，不反向改变当前轮换游标。

### 15.7 特殊通知数量

- 决策：同一规则同一日期支持一条特殊通知；节假日区间批量创建逐日记录，本期不支持同日 N 条。

### 15.8 固定多人值班的人员跳过

- 决策：只移除被跳过人员；仍有人员时不额外补人，全部被移除时才按下一排班单元补位。

## 17. 2026-08-22 全系统实时生效补充需求

### 17.1 影响范围

保存一版已生效的节假日跳过配置后，下列自动路径必须共同使用同一份全局停排日结果：

1. 自动值班开始/结束通知及其排班预览、下一次执行时间。
2. `task_create_notify` 自动任务创建并通知规则，包括仅执行、执行并通知和仅通知三种动作模式。
3. 主任务成功后激活的子通知，包括子通知列表倒计时和真实发送时间。
4. 子通知主任务前置条件兜底判定使用的上一次/下一次主任务执行时间。
5. 设置页保存日历后刷新规则列表，所有倒计时无需重启服务即可反映新配置。

### 17.2 普通自动规则顺延语义

- 普通自动规则原计划落在法定节假日、默认周末或手动停排日时，不在停排日执行。
- 该次计划顺延至其后的第一个非停排日期，保留原规则的时分秒。
- 连续停排日只顺延到第一个有效日期；若多个原计划被同一段连续停排压缩到同一天，同一规则只执行一次。
- `force_work` 取消默认停排后，原计划恢复在该日期执行。
- 年度日历尚无已生效修订时继续沿用旧逻辑，不因仅存在内置节假日快照而改变现有规则。

### 17.3 子通知语义

- 子通知只有在主任务已成功激活后才参与排期。
- 子通知原计划落在全局停排日时，按与主任务相同规则顺延到下一非停排日。
- 顺延只改变本轮实际发送日期，不改变用户配置的星期/月日模板。
- 子通知列表和编辑界面的 `next_run_at` 必须显示顺延后的实际时间。

### 17.4 明确不受自动跳过影响的操作

- 管理员主动点击的“测试执行”“测试发送 webhook”和“子通知测试发送”仍立即执行，因为它们是显式人工操作。
- 特殊日期通知的用途就是在停排日发送节日/标记日文案，因此继续独立执行，不被整日停排阻断。
- 人员单日跳过和临时换班仍只属于自动值班规则，不扩展到普通自动任务。

### 17.5 验收补充

1. 周末、法定节假日、手动停排、取消默认停排四种日期状态分别验证。
2. 自动值班、普通主任务、子通知、特殊日期通知分别验证真实运行时路径。
3. 日历保存前后对比普通主任务和子通知的下一次执行时间，必须立即变化且无需重启。
4. 使用本机隔离 webhook；测试规则、日志、任务、修订和通知记录全部清理，不影响现有业务数据。

### 18.2 日期状态优先级

1. 用户手动停排 `manual_skip`：停排。

- 自动任务、实际通知、下一次执行时间等运行时入口不得默认启用展示投影，只允许全年日历显式请求。
- 2026 年验收样本共 6 个补班日：`01-04`、`02-14`、`02-28`、`05-09`、`09-20`、`10-10` 均应显示人员；春节、劳动节、端午节、国庆节抽检日期仍应无人且无通知事件。
