# REQ-066 周期加权交付率与历史说明（冻结需求）

日期：2026-09-17。状态：用户已明确批准按诊断及附图周期公式纠正；四轮设计反馈、本地实现与定向验收完成，未部署生产。本轮确认直接授权下述既定纠正，不重复要求许可。实际结果见[执行验收](../@test/period_weighted_delivery_20260917/execution.md)及[开发记录](../@development/period_weighted_delivery_20260917.md)。

## 1. 冻结口径

- 周期统计的 **加权交付率＝加权已交付工时÷当前范围应交付工时×100%**。普通有版本按同人、版本、标题累计工时乘所选范围最新周期需求进度；五类“请假、培训、公司会议、出差、团建”全额计入一次；普通无版本不进入加权工时。组/岗位/部门按工时及容量直接合并，个人只算本人。
- 人群与工作日规则不变：当前非离职且选中范围有记录的人纳入；该人纳入后的完整所选范围工作日每天8小时计应交付。已纳入的人某周缺填仍保留该周容量，该周加权工时为0，不因未填写缩小分母；整个范围无记录的人仍不纳入。
- 应交付工时>0且日历有效时，即使有效/加权工时为0也显示0%；应交付为0或日历 `invalid_period` 时显示“—”。允许超过100%，如实显示。
- 历史已保存普通有版本记录的null进度按100%参与加权计算，原DB仍为null；明确0仍为0。原真实已知进度、覆盖率、missing等API字段不伪造为100%，不回填历史。
- 卡片与弹窗左上四指标继续同一行，保留总工时、人员表和底部原列表页签。原脚注中“需求填报进度— / 覆盖0%”不再作为常驻信息；`missingProgressHours>0` 时改为简短 **“历史未填进度按100%计”**，无历史缺失且有真实需求进度时保留该进度文本，全空则不显示脚注。覆盖率只放悬浮说明；Tips同时解释真实填报进度、覆盖率、缺失工时及历史默认值。
- 更新统计卡片、详情、逐人、API、Excel的同名指标公式与说明，保持同范围同值。填写页“预估加权工时完成度”本来按应填容量，维持现有预估逻辑和紧凑说明。

## 2. 不变边界与覆盖关系

本条替换 REQ-065 的统计加权分母及常驻脚注展示，其余已确认功能不变：新普通正式输入仅10..100、原普通null兼容及原有值清空防绕过、五类手填工时与固定日期版本、当前状态过滤、日期范围、最新周期分组、去重、角色权限、排序和导出原记录。无数据库结构变更、历史数据写入、生产操作或演示数据插入；不动无关 `ReportPage.vue` 脏改。
