# REQ-071 五类工时后缀识别与可编辑进度（冻结需求）

2026-09-21。状态：四轮设计反哺完成，按用户"四轮后执行最小范围开发"授权采用默认决策 D1~D4 进入开发。四轮记录：`docs/@test/full_credit_suffix_progress_20260921/round1~4.md`。

## 1. 用户原始需求

填写页当前仅标题精确为 请假、培训、公司会议、出差、团建 时视为有效工时。改为：标题等于上述词组，或标题末尾（忽略尾部特殊字符和数字）以上述词组结尾——从后往前数最近的简体或繁体汉字文本是上述词组即命中（如 `XXXX请假`、`XXXX“请假`、`xxxxx”请假“`、`XXXXX‘请假’@@`、`XXXXX请假【【23`），同样给默认版本号、自己填工时。这些记录交付进度默认 100%、可编辑；进度不到 100% 时与其他未完成需求同样处理。

## 2. 识别规则

- `title.trim()` → 剥离**尾部所有非汉字字符**（数字、ASCII/全角标点、引号、括号、空白、英文字母；D1）→ 繁体归一（請→请、訓→训、會→会、議→议、團→团）→ 以 `请假|培训|公司会议|出差|团建` 之一结尾即命中。
- 命中示例：`请假`、`张三请假`、`张三“请假`、`张三”请假“`、`张三‘请假’@@`、`张三请假【【23`、`请假abc`、`出差（北京）`、`張三團建12`、`培訓`。
- 不命中：`培训系统开发`、`公司会议纪要`、`请假申请开发`、`出差报销`、`团建活动平台`、`请假开发`、`公司会`、纯符号/数字/空。
- 前后端同一规则；标题按原文（trim）保存，不改写。

## 3. 版本、PM/需求方、工时

- 版本仍自动 `vYYMMDD` 并锁定（REQ-064）。**新增**：带出的五类行提交时，若客户端版本形如 `vYYMMDD` 且该 `(标题, 版本)` 存在于本人已保存五类记录中，服务端沿用该版本（D3）；否则按今日重生成。客户端不能伪造不存在的版本。
- PM（研发）/需求方（AI 产品）继续"不适用"、为空。工时手填，规则不变。

## 4. 进度

- 默认 100，可编辑，合法集合与普通需求相同 {1,10,20,…,100}；提交/暂存/CRUD/导入省略或为空 → 100；非法值 400。
- 标题由普通改为五类：备份普通字段、进度置 100、版本自动；改回普通：恢复备份。
- 已存/草稿/带出的五类行按自身进度初始化；null → 100（带出且上次进度为 0 的行保留空并提示）。
- 历史五类记录 `delivery_progress` 仍为 null，DB 不回填；统计/详情读作 100%、状态"已完成"（D2）。

## 5. 统计与联动

- 有效已交付：五类全额计入（不变）。
- 加权交付率：五类按"同人+版本+标题"分组取所选范围最新周期进度加权（null 按 100），与普通需求一致。
- 需求总数、需求填报进度平均、进度覆盖率：五类继续排除（D4）。
- REQ-069 "查看未完成"列表与 REQ-070 跨周带出纳入进度 <100 的五类记录。
- MatchService 五类独立键逻辑不变。
