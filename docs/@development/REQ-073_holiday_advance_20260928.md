# REQ-073 工时收集自动任务：假期改为提前到假期前最后一个工作日执行

日期：2026-09-28。状态：已确认（用户选 B）。

## 现象与定位

- 生产设置页三条"自动生成下一周任务"（周五 14:00）在 9-28（周一）显示倒计时 4 小时；9-25（周五）未生成 39 周任务，用户 09:42 手动创建 39 周任务、09:58 停用三条规则。
- 服务器 `Asia/Shanghai`，Node 偏移 -480，MariaDB `SYSTEM/CST`，浏览器与服务端 `Date.now()` 一致；**无时区问题**。
- 根因：`DutyCalendarService.getGlobalScheduleSourceDates` 把停排日（法定假日/周末/手动停排）的执行时机**向后顺延**到下一个工作日。9-25~9-27 为中秋假期，周五规则被顺延到 9-28 周一，导致倒计时落在下周一、且周任务的生成时间跨周。

## 决策（四轮收敛）

1. 范围：仅 `task_type = task_create_notify` 主规则改为**向前提前**：若配置的执行日是停排日，则在该停排区间前最后一个工作日的相同时间执行。值班提醒、子通知维持原"向后顺延"（子通知是会前提醒，顺延到假期后首个工作日更合理）。
2. 定义：对工作日 T，来源日期集合 = `{T} ∪ {T+1, T+2, …（连续停排日）}`；规则的星期/日期匹配任一来源日即在 T 执行。停排日本身永不执行。
3. 幂等：某个停排区间只会映射到唯一的 T（区间前一天），不会重复；同一 T 若同时命中多个来源日（如周五、周日都配置）仍只执行一次（既有 run_log 幂等）。
4. 兼容：普通周五（后接周六、周日停排）来源集合含周五本身，行为不变；补班日（如 9-20 周日）为工作日，其来源集合仅含自身。
5. 周任务生成：`createNextWeeklyTask` 以"最新任务周 +1，且不超过当前周 +1"推进，提前执行时仍在本周内生成本周任务，周期区间不跨周。
6. 展示：设置页说明文案补充"执行日遇法定假日/周末则提前到假期前最后一个工作日"；倒计时逻辑不变（取 `next_run_at`）。
7. 不做：不改数据结构，不改值班日历规则，不补跑 9-25 任务（39 周任务已手动创建）。
