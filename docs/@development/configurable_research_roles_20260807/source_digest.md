1. 新增 `嵌入式软件工程师` 研发角色，并在全部页面、功能和报表中参与记录与统计。
2. 研发人员列表支持姓名、手机号码、角色、状态筛选。

5. 新增角色可用于新增研发人员，并进入全系统统计链路。
6. 部门全观的 AI产品经理工时分布图隐藏所有指标均为 0 的产品经理。
7. 先文档，后本地开发；不推送、不发布。

## 既有约束

- 非离职人员包含在职、留职、长假；0 工时仍需保留在人员口径中。
- 离职人员仅在历史有效时间范围且有数据时显示。
- 角色完整名称不得换行；空间不足时使用简称。
- 需求工时手动行整行可编辑、自动保存并全系统同步。
- 离线工时分析报告访问时按系统最新数据自动生成。

## 代码审计结论

- `staff.role` 当前为 ENUM，不能承载配置新增角色。
- 前后端角色定义均为静态常量。
- `match_groups` 使用四个固定 JSON 列，不能承载任意角色。
- 统计接口基于 `WorkRecord + Staff.role`，适合改造成动态角色汇总。
- 需求报表、Excel、全量备份和离线 HTML 生成器均存在固定三角色结构。
- 离线报告刷新签名目前包含人员角色但不包含角色显示配置。
- PM 图表直接使用后端预初始化的全部 PM，导致全 0 项占据横轴。

## 决策

- 使用稳定 key + 可编辑显示元数据，不用角色名称作为业务外键。
- 新增 `staff_roles` 与 `match_groups.role_buckets`，保留旧列兼容。
- 不提供删除/停用，避免没有迁移策略时产生孤立历史数据。
- PM 零值过滤只作用于图表及对应图表导出，不改变业务名单。
