# REQ-060 工时完成度交付记录

日期：2026-09-16。范围：本地实现与验证。状态：READY（本次本地验收范围）。

## 结果

按用户确认分别展示工时完成度与交付综合进度。5 工作日周：32/40=80%，40/40=100%，48/40=120%，超额20%。跨人跨周采用总已填/总应填，同一人员同一工作日基准去重，未填人员保留分母。

## 实现

- `backend/src/services/WorkHoursCompletionService.js` 统一计算人员、工作日、假期补班、跨周汇总、空分母与估算状态。使用现有节假日缓存与人员状态，读取过程中不发起同步、不写业务记录。
- `backend/src/routes/stats.js` 的部门、个人、归属人、追踪与 Excel 接口返回同口径指标；修正全部范围仍被 taskId 限制、岗位筛选遗漏与需求方改名权重映射。
- `backend/src/routes/fill.js`、`tasks.js` 提供当前/历史填写和任务详情容量。历史工时不继承交付进度100%的显示覆盖。
- 前端 `HoursCompletion.vue`、`ProgressExplanation.vue`、`utils/workHours.js` 统一比例、超额、基准和说明；统计视图、分析弹窗、填写表单预览/历史、任务详情接入，其他工时页复用说明。
- 版本交付卡片使用原始有效工时直接加权：1h@100% + 9h空 + 10h@0% 的结果为9.09%；不再把缺进度工时带回二次加权分母。
- Excel 增加两种指标、公式和人员周期容量；容量汇总列按人员日期去重，版本/需求方子集明确为同范围应填工时的贡献占比。
- 移动端优化进度卡片、全局导航与填写按钮换行，使新增指标可读。

## 审查与修复

1. 历史任务含周日～周六格式，开始日期锚点会错取上一自然周。改用任务结束日期归周，覆盖第9周、第15周和跨年历史用例。
2. 需求方目录改名不重写历史记录，名称与旧权重可能失配。读取时按稳定ID及原始同序名称映射权重，主列表/图表/分析/导出一致保留75/25分配。
3. 有效与无效周期混合时，已知容量不足以支持确定比例。现显示“待核实”，比例为空，保留已填与已知应填工时。
4. 独立审查代理复核：上述两项阻塞与一项建议均关闭。

## 口径边界

- 日期缺官方快照时显示工作日估算和“待核实”；已有人员历史没有入职日期，不把建档时间当入职日。未建任务的周不额外纳入分母。
- 长假、留职沿用现有可填报人员口径，值班停排不作为全员休假依据。
- 界面复杂交互使用合成浏览器数据验证，真实API使用只读现有数据核对；没有执行生产发布或完整生产环境认证。
