# REQ-065 加权交付率与四指标同行开发记录

2026-09-17。状态：本地实现与定向验收完成；未部署生产。

## 需求与实现

按用户已确认的纠正口径，在[冻结需求](../@demand/weighted_delivery_refinement_20260917.md)、[计划](../@plan/weighted_delivery_refinement_20260917.md)及四轮设计反馈落盘后实现。工作区有此前未提交文件，保留它们；本轮只做下面的必要变更，累计Git差异不能全称本轮新代码。

- 统计加权交付率改为Σ（有效工时×需求进度）÷有效工时，部门/岗位直接合并工时，个人各算本人。普通无版本排除，五类全额计入一次。所有有效需求进度100%时即100%；有效工时为0显示“—”，不依赖应填容量。有效交付率仍除以应交付工时。
- 历史null仅计算时按100%，原DB及真实进度/覆盖率不回填；明确0仍按0。沿用同人/版本/标题累计工时与所选范围最新周期进度。
- 正式填写普通需求须10..100、每10%一档；五类不适用。仅服务端查到的原始普通null可原样兼容，不允许已填进度清空、特殊改普通或伪造旧ID套用豁免。历史0读取保留，显式重提0需修改，管理PUT省略原进度可保持。
- 填表“预估加权工时完成度”仍除以所属周期应填工时；新增缺进度继续待补。前端保留加载时原空标记用于提示，服务端独立决定豁免。Tips和Excel说明明确两种分母。
- 外卡及弹窗左上四指标同行，保留大字总工时、逐人表和原页签/列表。窄卡使用容器字号适配；手机外卡单列布局，卡内四指标仍同行。
