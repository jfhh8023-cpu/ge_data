## 触发需求

用户要求保留现有每周固定值班方式，并新增轮换模式：可选择周一到周一/周二/周三/周四/周五/周六/周日的排班区间，按人员勾选顺序逐日轮换；每周概览显示当前自然周，提供后三周排期；候选人仅使用在职研发人员。

需求归档：`docs/@demand/auto_duty_weekly_rotation_20260803.md`。

## 实施结果

| 需求 | 本地实现 |
| --- | --- |
| 固定模式保留 | 旧 `duty_config` 缺少模式字段时归一为 `fixed`，原周/月固定配置不变 |
| 新增轮换模式 | 每周星期值班配置在“值班对象”右侧新增“固定模式/轮换模式”单选项，月度配置不变 |
| 排班区间 | 支持周一到周一至周一到周日共 7 种区间 |
| 勾选顺序 | 复选框与姓名之间显示蓝底白字序号；取消后自动重排，重新勾选追加到队尾 |
| 连续轮换 | 使用锚点周一、周偏移和星期偏移计算序号，跨自然周连续，不因页面刷新重置 |
| 非排班日 | 超出区间、无候选人员或失效历史人员统一显示“未配置/跳过”，不生成动态值班项 |
| 当前周说明 | 每周值班概览标题右侧显示当前 ISO 自然周和每周一更新说明 |
| 后续排期 | “后续”弹窗按自然周分组展示下一周起连续三周，每周固定 7 天；当前第 32 周时展示第 33、34、35 周 |
| 调度同步 | 后端保存、日期匹配、下次执行时间和定时事件均通过同一轮换规则解析 |

## 数据与算法

未新增数据库列，继续使用 `auto_task_rules.duty_config` JSON，新增：

- `weekly_mode`: `fixed` / `rotation`
- `weekly_rotation.end_weekday`: 1-7
- `weekly_rotation.staff_ids`: 按勾选顺序保存的人员 ID
- `weekly_rotation.start_date`: 归一到锚点自然周周一

轮换下标：`(周偏移 × 区间天数 + 星期偏移) mod 人员数`。区间外日期直接返回空人员；区间内仍沿用对应星期的通知时间、发送策略和文案。
