## 数据保护边界

1. 不上传或导入本地数据库、SQL dump、备份目录、日志、报告快照、`.env` 或本地业务数据。
2. 不执行 `backend/init.sql`、`deploy/devtracker_full.sql` 或任何全量数据导入脚本。
3. 发布前必须完整备份生产数据库、生产后端文件、PM2/Nginx 配置和服务器状态，并校验 dump 完整性。
4. 发布命令固定使用 `--skip-db`；应用启动仅通过 Sequelize `sync()` 创建缺失的新表，不删除、不清空、不覆盖现有表和记录。
5. 仅操作 `/opt/devtracker`、PM2 进程 `devtracker` 和 DevTracker Nginx 路由，不影响服务器其他项目。
6. 生产实时数据变化只记录差异，不回滚、不覆盖；发版前后必须核对核心表行数和工时总和。
