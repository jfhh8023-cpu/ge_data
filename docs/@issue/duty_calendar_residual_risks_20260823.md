# 节假日日历与排班剩余风险

## 记录信息

- 日期：2026-08-23。
- 状态：本地功能通过，以下风险未纳入本轮最小范围。
- 关联需求：`docs/@demand/duty_holiday_calendar_and_schedule_exceptions_20260821.md`。
- 关联测试：`docs/@test/duty_calendar_20260823/results.jsonl`。

## R-01 服务端统一鉴权缺口

- 现状：设置页管理员入口和多数既有业务 API 主要依赖前端入口控制，后端没有统一身份认证与授权中间件。
- 风险：知道接口地址的客户端可能绕过前端入口直接请求写接口。
- 本轮处理：未在日历接口单独创造一套与全系统不一致的临时身份体系；新增输入校验、乐观锁、事务和 webhook 服务端白名单不能替代身份认证。
- 建议门禁：发布前设计统一会话/令牌认证、管理员权限校验、审计日志和 CSRF 防护，并覆盖全系统写接口。

## R-02 跨年官方日期与轮换游标

- 现状：年度官方快照以年份读取；跨年长假通知和轮换游标跨 12 月/1 月的组合尚未形成独立自动化矩阵。
- 风险：极端跨年通知或生效版本可能造成前后年度边界显示/顺延不一致。
- 建议门禁：增加 12 月 25 日至次年 1 月 15 日的连续预览、通知事件、人员跳过和临时换班回归。

## R-03 多实例官方同步互斥

- 现状：单进程内有缓存与重试，数据库保存可幂等；尚无跨实例分布式锁。
- 风险：多实例同时发现新通知时会重复抓取和竞争更新，虽不会写入未校验数据，但会增加外部请求和审计噪声。
- 建议门禁：生产若以多实例运行，增加数据库租约或分布式锁，并记录实例 ID、请求 ID 和刷新结果。

## 已关闭的审查项

- 任意 webhook SSRF：已改为服务端严格钉钉 HTTPS 白名单、公共 DNS 校验；本地回归接收器须显式测试开关。
- 未来无官方数据仍可保存：前端保存按钮禁用，后端返回 409，不可通过接口绕过。
- 官方页面重定向和缓存校验：逐跳验证 `gov.cn`，校验和不匹配拒绝使用，失败保留最近有效缓存并标记 `refresh_failed`。
- `start_only` 残留结束通知：前后端均按 `send_mode` 过滤，自动化与浏览器验证通过。
